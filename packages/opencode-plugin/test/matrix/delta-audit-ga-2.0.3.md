## Verdict

The scope, host API, and discovery metadata changed at GA. Loader shape, Effect-first selection, typed RPC registration, tool replacement, and interruption remain usable after updating specifiers. A plugin-initiated permission-request API is still absent (`expected_fail:upstream#37164`).

## Relied-on contract diff

1. **Permission endpoint — changed.** The GA Effect `Context` exposes a `permission` domain, but that domain only has `list`, `get`, `reply`, `rules`, and `hook`; it does not expose `ask`, `assert`, `create`, or a general client. The server-side plugin context implements exactly those five members. A plugin cannot initiate the permission prompt used by AFT's hoisted mutators. Citations: `@opencode/plugin@2.0.3/dist/effect/plugin.d.ts:24-50`, `@opencode/plugin@2.0.3/dist/effect/permission.d.ts:16-21`, `@opencode/core@2.0.3/dist/chunks/mime-pe4b2cf4.js:403-409`. Classification: `expected_fail:upstream#37164`.
2. **Effect entry precedence — preserved after scope rename.** The module decoder accepts default `{id,effect}` or `{id,setup}`, resolves `server` first, and chooses Effect when the value has an `effect` key. `tui` and `rpc` features come from resolvable subpaths. Citations: `@opencode/core@2.0.3/dist/chunks/mime-771dt0vh.js:54-65,72-101`; resolver order: `@opencode/plugin@2.0.3/dist/host.js:4-32`.
3. **Typed RPC — preserved through the Effect context, discovery split clarified.** Method dispatch is installed by `context.rpc.register`; the server context combines the RPC client and registration method. A resolvable `./rpc` only marks `features.rpc` during module loading. AFT therefore keeps `getStatus` registration in the server Effect and does not add a redundant `./rpc` export. Citations: `@opencode/plugin@2.0.3/dist/effect/rpc.d.ts:6-18`, `@opencode/core@2.0.3/dist/chunks/mime-pe4b2cf4.js:203-208`, `@opencode/core@2.0.3/dist/chunks/mime-771dt0vh.js:88-101`.
4. **Interruption ordering — preserved; HTTP surface renamed.** On provider interruption the runner interrupts tool fibers before awaiting all tool fibers, retries interruption if the join fails, then records unsettled-tool and assistant failures. GA renamed the HTTP control from `/api/session/:sessionID/abort` to `POST /api/session/:sessionID/interrupt`; its response is `{ interrupted: boolean }`, where `false` is the idle no-op. Citations: `@opencode/core@2.0.3/dist/chunks/mime-hf6kd63r.js:69-70,98-109,137-145`, `@opencode/protocol@2.0.3/dist/groups/session.js:511-526`.
5. **Built-in replacement — preserved through `ToolEditor.remove`.** The GA editor supports list/get/namespace/add/update/remove, and the host exposes the transform plus execute hooks. AFT can continue removing built-ins before adding projected replacements. Citations: `@opencode/plugin@2.0.3/dist/effect/tool.d.ts:7-19,20-51`, `@opencode/core@2.0.3/dist/chunks/mime-pe4b2cf4.js:442-446`.
6. **`path` header keys — rendering contract changed.** The beta renderer source paths are not published in the GA core/plugin tarballs. GA's read tool puts the requested path into model content while metadata only carries truncation; edit carries file diffs in `metadata.files`. AFT's own registered schemas and transcripts, rather than removed beta renderer line numbers, govern its path display. Citations: `@opencode/core@2.0.3/dist/chunks/mime-3zpd0x8a.js:78-116`, `@opencode/core@2.0.3/dist/chunks/mime-2b4vkxet.js:138-190`.
7. **Inert Effect dependency — changed package owner, V1 isolation retained.** The GA plugin declares exact `effect@4.0.0-rc.112`; AFT keeps Effect as a normal dependency and keeps the V1 `@opencode-ai/plugin` line separate. OpenTUI and Solid remain normal AFT dependencies, not peer externals. Citations: `@opencode/plugin@2.0.3/package.json:44-59`, `packages/opencode-plugin/package.json:37-60,76-80`.
8. **SessionID-scoped permission creation — request half removed from plugin API.** GA still checks `sessionID` ownership for `get` and `reply`, but the plugin context has no creation method. AFT cannot reproduce beta's `permission.create` request flow on the real GA context. Citation: `@opencode/core@2.0.3/dist/chunks/mime-pe4b2cf4.js:403-409`. Classification: `expected_fail:upstream#37164`.
9. **Dev/beta cadence — superseded by stable GA.** The coherent V2 packages are now under `@opencode/*`; both unpacked package manifests identify version `2.0.3`, while `@opencode-ai/plugin` latest remains on the V1 line. Citations: `@opencode/plugin@2.0.3/package.json:3-4,44-53`, `@opencode/core@2.0.3/package.json:3-4,104-127`.
10. **TUI keymap layers — component-scoped, and never legal from `setup`.** The TUI plugin definition is `{id, setup}`, so `setup` is the only code the host calls directly (`@opencode/plugin@2.0.3/dist/tui/plugin.d.ts:4-7`). `Keymap.layer` is not a registration call: it "creates a reactive keymap layer owned by the calling component" (`@opencode/plugin@2.0.3/dist/tui/context.d.ts:372-374`). The host forwards the bare Solid primitive on the plugin context — every sibling (`dispatch`, `shortcuts`, `commands`, `pending`, `active`, `mode`) is bound to host state, `layer` alone is passed through (`@opencode/cli@2.0.3/bin/opencode.exe` @127867898, `keymap:{layer:Ae.createLayer,dispatch:f.keymap.dispatch,…}`) — and that primitive reads the keymap through Solid's context and throws when none is current (`… @125115721`, `function He(){let t=Br(hr);if(!t)throw Error("Keymap.Provider is missing")}`, consumed by the layer factory at `… @125112184`). `setup` runs from a detached async continuation, so no Solid owner and no provider are in scope (`… @127881096`, `async function hqt(i,f,g){try{return await i.setup(f)}…`). The legal home is a render the host mounts: the plugin context wraps `ui.slot`, `ui.router.register` and `ui.dialog.show` renders in its own provider, and the host renders those inside `Keymap.Provider`. `app` is the slot mounted for the whole session independent of route (`@opencode/plugin@2.0.3/dist/tui/context.d.ts:161-162`; mount at `@opencode/cli@2.0.3/bin/opencode.exe` @128220046, `s(ko,{path:"app"})`). GA's own built-ins do exactly this: `opencode.plugins`, `opencode.stats`, `opencode.diffs` and `opencode.storybook` each claim `append:"app"` and call `keymap.layer` from that render (`… @127541568`, `setup(i){i.ui.slot({append:"app",render:()=>s(tLt,{context:i})})}` where `tLt` calls `keymap.layer` and returns `null`). Classification: **not a GA regression.** `@opencode-ai/cli@0.0.0-beta-19234` carries the identical forwarding (`bin/opencode2.exe` @128199739, `keymap:{layer:ge.createLayer,…}`) and the identical `{id, setup}` definition (`@opencode-ai/plugin@0.0.0-beta-19234/dist/tui/plugin.d.ts:4-7`), so a setup-time `keymap.layer` never worked on any V2 host.
11. **TUI keymap layer mode — `base` by default, which hides palette commands.** A layer without a `mode` is limited to the host's base input mode; `"global"` opts out (`@opencode/plugin@2.0.3/dist/tui/context.d.ts:347-349`). The command palette is a dialog, and the dialog host pushes the `modal` mode while any dialog is open (`@opencode/cli@2.0.3/bin/opencode.exe` @127322692, `x.mode.push("modal")`), while the palette itself lists only commands reachable in the current mode (`… @128043101`, `function sue(){let i=Ae.useCommands(),f=Ae.useShortcuts()…}`, over `getCommandEntries({visibility:"reachable"})` at `… @125114276`). A palette or slash command therefore needs `mode:"global"`, which is what all four GA built-ins above set.
12. **TUI discovery — directory targets are resolved literally, and file targets are skipped.** `Host.resolve` joins the subpath onto the target directory when the target has no package name, and returns `undefined` for the whole feature when the join does not resolve (`@opencode/plugin@2.0.3/dist/host.js:4-32`, especially `path.resolve(target.directory, subpath || "index")` at line 9 and `entry(["tui"])` at line 29). A local target that stats as a file is dropped before that, so a V2 TUI target must be a directory rather than an entry file (`@opencode/cli@2.0.3/bin/opencode.exe` @127876342, `if(we&&await pqt(we).then((Ft)=>Ft.isFile(),…))continue`). An unresolvable TUI subpath is reported as `unsupported` with nothing written to the log, so a package without a root `tui` entry loses the feature silently.
13. **TUI slot and form renames, 2.0.3 -> 2.0.11 — no AFT dependency.** The TUI context declarations differ in exactly four places: `FormReplyInput`/`FormCancelInput` became `SessionFormReplyInput`/`SessionFormCancelInput` on `data.session.form.reply`/`cancel`, the `home.footer.status` slot was added to `SlotMap`, and `ToastOptions` gained `sessionID`. Citations: `@opencode/plugin@2.0.3/dist/tui/context.d.ts:1,69-70,161-178,236-241` against `@opencode/plugin@2.0.11/dist/tui/context.d.ts:1,69-70,161-179,237-244`. AFT's TUI touches none of them: it reads no `context.data`, claims only `app`, `prompt.footer.status` and `sidebar.content`, and uses `ui.dialog.alert` rather than `ui.toast`. The keymap contract itself is byte-identical across the two versions apart from line offsets.

## Host isolation

A throwaway `HOME` plus all four XDG roots does not isolate a V2 TUI host by itself. The TUI attaches to a managed background service whose port is a constant per release channel — the pinned GA line resolves to 49374 on every machine, `local` to 49375, and any other channel to a hash-derived port (`@opencode/cli@2.0.3/bin/opencode.exe` @124619997, `function hH(e=da){if(e==="latest"||…)return 49374;if(e==="local")return 49375;return 1e4+…}`). Two isolated runs, or one run beside the operator's own editor, therefore contend for a single port, and the loser either fails to start its service or silently attaches to the winner's — defeating the XDG roots, because the database then belongs to the other process. The service config that overrides the port does live under the isolated config root (`… @124621268`, `configFile:u.join(n.config,i)` with `i="service.json"`), so the matrix reserves a free loopback port per row and writes it to `$XDG_CONFIG_HOME/opencode/service.json` (`packages/opencode-plugin/test/load-matrix/load-matrix.ts`, `writeV2HostConfig`).

## Discovery audit

`oc-plugin` has zero occurrences in the unpacked `@opencode/core@2.0.3/dist` and `@opencode/plugin@2.0.3/dist` trees. GA discovery has two branches, chosen by whether the target carries a package name: a named target is resolved through the package exports map (`<pkg>/server` then `<pkg>`, `<pkg>/tui`, `<pkg>/rpc`), while a directory target has the same subpaths joined onto it as literal paths (`<dir>/server` then `<dir>/index`, `<dir>/tui`, `<dir>/rpc`). Both branches swallow every resolution error and report the feature as absent (`@opencode/plugin@2.0.3/dist/host.js:4-32`).

## Note on binary citations

The GA TUI host is published only as a compiled executable: `@opencode/cli@2.0.3` ships `bin/opencode.exe` with no `dist` tree, and `@opencode/plugin@2.0.3/dist/tui/` contains the context types plus a four-function Solid shim, not the host implementation. Points 10-12 and the isolation note therefore cite that executable by byte offset together with the literal text at it, so each can be re-found with a byte search rather than trusted on the offset alone.
