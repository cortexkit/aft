# shells/v1 serializer samples

These four sample sets are generated by the Rust payload serializers in
`crates/aft/src/subc/shells/wire.rs`. `SHA256SUMS` hashes the exact JSON bytes,
including the trailing newline. The `tag`, `method`, `request`, and `reply`
fields are corpus notation, not an additional wire envelope.

- `list.json`: agent and worker rows, every shell kind, a remote job queued
  before acceptance, a masked command, a 2 KiB truncated command, and an
  unattributed session.
- `watch.json`: split initial resync, new row, queued-to-running change, end,
  removal, status change, and lagged resync. `part` starts at zero. Only the
  final resync part carries a cursor; the cursor is opaque to the client.
- `output.json`: three subscriptions (ANSI kept, ANSI stripped, and PTY).
  The first two explicitly resume at stdout byte 16, omitting older output.
  A euro sign ends the first chunk and a complete colour escape starts the
  next. Offsets count raw UTF-8 file bytes, not the length of displayed text.
  PTY cursor coordinates are zero-based; `exit.signal`, when known, is numeric.
- `errors.json`: the Error payload for an agent-scoped route, an empty list
  for an unknown agent, and the remaining defined Error payloads. An unknown
  agent is not an error.

On the management route, one-shot replies use the same correlated Response
envelope as permissions/v1 (`{"result": <reply>}`). Watch and output entries
are correlated StreamData payloads, followed by a reliable StreamEnd when
the subscription finishes. Error payloads use Error frames, not Responses.
All code-valued fields remain open strings. Unknown optional facts are
absent, not null and not inferred.

Regenerate deliberately, review the changes, then commit all five artifacts:

```sh
cargo test -p agent-file-tools --lib -- shells_v1_regenerate_samples --ignored
```

The non-ignored `shells_v1_serializers_match_committed_samples` test fails on
either serializer drift or checksum drift.
