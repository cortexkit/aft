# shells/v1 serializer samples

These four sample sets are generated by the Rust payload serializers in
`crates/aft/src/subc/shells/wire.rs`. `SHA256SUMS` hashes the exact JSON bytes,
including the trailing newline. The `tag`, `method`, `request`, and `reply`
fields are corpus notation, not an additional wire envelope.

- `list.json`: agent and worker rows, every shell kind, a remote job queued
  before acceptance, a masked command, a 2 KiB truncated command, and an
  unattributed session.
- `watch.json`: split initial resync, new row, queued-to-running change, end,
  removal after the 30-minute retention window, status change, and lagged
  resync. `part` starts at zero. Only the final resync part carries a cursor;
  the cursor is opaque to the client.
- `output.json`: four subscriptions (ANSI kept, ANSI stripped, a pseudo-terminal
  (PTY) screen, and default backfill without a resume offset).
  The first two explicitly resume at stdout byte 16, omitting older output.
  A euro sign ends the first chunk and a complete colour escape starts the
  next. Offsets count raw UTF-8 file bytes, not the length of displayed text.
  The default backfill contains the last 64 KiB, split into four 16 KiB chunks.
  PTY cursor coordinates are zero-based; `exit.signal`, when known, is numeric.
- `errors.json`: the Error payload for an agent-scoped route, an empty list
  for an unknown agent, and the remaining defined Error payloads. An unknown
  agent is not an error.

On the management route, one-shot replies use the same correlated Response
envelope as permissions/v1 (`{"result": <reply>}`). Watch and output entries
are correlated StreamData payloads, followed by a reliable StreamEnd when
the subscription finishes. Error payloads use Error frames, not Responses.
All code-valued fields remain open strings. Unknown optional facts are
absent, not null and not inferred.

`max_chunk_bytes` accepts 64 through 65536 bytes, with a default of 16384.
The edge samples use 64-byte chunks: raw stdout offsets advance 16 → 80 → 95
whether ANSI is kept or stripped. If masking cannot safely decide a range,
its chunk text is `[output withheld: masking context unavailable]`, not raw
output. The chunk still advances the raw offsets over the withheld range.
A stream retains a trailing buffer as long as its longest known secret, so a
credential arriving across two chunks can be masked before either part is
shown. That buffer and the masking context use bounded memory; uncertain
credential formats are never emitted as raw bytes. A remote host is absent
whenever the execution protocol has not supplied an actual placement name.

With `agent_ids` supplied, `include_workers` defaults to `false`: only the
named agents' own shells are included. `include_workers: true` also includes
their workers. With `agent_ids` absent, every holder is included, including
workers and unattributed sessions.

Root-agent sidebar hints share a 256-association query budget across bound
roots, restricted to live scopes. When that budget is exhausted, the affected
root status objects include `agent_ids_truncated: true`; earlier roots whose
lists were fully visited omit it. Later roots may have no listed IDs yet and
still carry the flag because their associations have not been fully visited.
Agent-filtered status retains these incomplete roots even when the requested
agent is not among the shown IDs: an incomplete list cannot prove absence.
For example, this root-status fragment says that the known IDs are incomplete:

```json
{"agent_ids": ["agent-alf"], "agent_ids_truncated": true}
```

This optional edge case is documented here without changing the hashed samples.

Regenerate deliberately, review the changes, then commit all five artifacts:

```sh
cargo test -p agent-file-tools --lib -- shells_v1_regenerate_samples --ignored
```

The non-ignored `shells_v1_serializers_match_committed_samples` test fails on
either serializer drift or checksum drift.
