# FSEvents overflow during an isolated Mason build (2026-09-12)

## Question and constraints

This run measured whether one clean `cargo build --release -p agent-file-tools` makes independent AFT FSEvents streams fall behind, and whether any resulting `Rescan` is tagged `kernel_dropped` or `user_dropped`. The production SubC daemon (PID 25476) and its long-lived AFT module (PID 62424) were observed read-only and were not restarted. Because that live module predates this instrumentation, four instrumented standalone AFT processes supplied typed counters while the live log supplied a same-window overflow cross-check.

Immediately before the standalone run, `subc-probe --health-probe aft` reported 69 actor roots, 68 live watchers, 61 root details omitted by the health cap, and process RSS of 2,463,776,768 bytes. It had no `watcher` objects, confirming that PID 62424 was the pre-instrumentation binary.

The old line has no reason field, so this event cannot be counted as directly typed evidence. Under the experiment premise that `KernelDropped` is visible machine-wide, the fact that none of four concurrently draining instrumented streams received `Rescan` while only the long-lived production consumer overflowed makes that one event consistent with a consumer-local `UserDropped`, not `KernelDropped`. Including that correlation as inference rather than direct telemetry gives **kernel 0 vs user 1 inferred**.

## Conclusion

`UserDropped` is the supported dominant explanation for this run: the watched build delivered 34,888 raw events to its own fast standalone consumer without a rescan, all three unrelated instrumented streams also stayed at zero rescans, while only the long-lived production AFT consumer logged one untyped overflow; a machine-wide `KernelDropped` should have appeared on the instrumented streams too. The directly typed count remains kernel 0 vs user 0 (the production event is user-dropped by correlation, not by its legacy log), so the next task should turn **latency/coalescing first** to give the consumer time to drain bursts. Exclusions can reduce downstream path work but did not stop 34,549 invalidating events from reaching the callback, and cheaper rescan addresses the cost after a drop rather than the consumer-local backlog that this run isolates.
