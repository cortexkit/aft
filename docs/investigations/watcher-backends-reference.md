## What AFT should take

AFT’s notify FSEvents path already requests file events with no defer, but its drop contract stops at a caller-visible `Rescan` marker rather than the journal replay or full crawl shown in the macOS table.

For FSEvents exclusions, Watchman’s deterministic, capped list is the safe reference; parcel-watcher passes an uncapped unordered set even though the API limit is eight.

On inotify overflow, Watchman’s root recrawl gives a concrete answer to “what changed,” whereas notify delegates that answer and parcel-watcher silently discards the overflow.

For inotify watch exhaustion, notify’s `MaxFilesWatch` is explicit, while Watchman additionally makes the kernel limit and non-recoverable state actionable.

AFT’s current Windows backend has no explicit `ERROR_NOTIFY_ENUM_DIR` recovery, while Watchman handles both that error and zero-byte overflow with a full recrawl.

If batching is needed, the tables show it is a separate policy: parcel-watcher applies 50/500 ms delivery debounce on all three OSes and Watchman adds 30 ms only in its Windows reader, while notify’s native backends emit directly.
