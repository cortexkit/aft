# Worker guide: AFT

The commands to build, check and test this repository, the commands not to use, and how to tell that a check really ran. Use the exact commands here. Never substitute a bare package-runner name (`npx biome`, `npx tsc`): from a package folder it can fetch an unrelated npm package and "pass" without checking anything.

A check that prints nothing and exits 0 is not a pass unless this guide says that check is silent on success. Report the version line and the number of checks run.

## Required before every delivery

CI is the final arbiter, not the first debugger. **Run `scripts/prepush.sh fast` locally and every server lane below before delivery.** Launch the mandatory `fast-compile` server half of the fast phase first, in parallel with the full lanes. A delivery without its result and all full-lane results is incomplete. Commit first so every server snapshots the same revision; after a fix, rerun the affected checks. Paste each lane's final `GATE PASSED` or `GATE FAILED: ...` line in your report, with its time and any blocker. A failed or unavailable lane is not a pass.

Both fast halves stop on the first failure. Local fast is source-only: formatting, lint, frozen lockfiles, workspace typechecking, source-generated byte checks, tracking/fragment/descriptor/fixture guards and publication input validation. It may build the JavaScript bridge, but never compiles native Rust. Server fast-compile runs `cargo check --tests` for the no-explicit-feature set, every CI feature/combination, and Windows target equivalents; it also runs CI's workflow regression scripts, which need server process permissions. Each feature set gets a named result line. Native hashline, catalog-reply and Rich UI carrier verification belongs to the Rust lanes because those checks need compiled generators or tests.

Launch independent lanes in parallel with `bash` calls (use `background: true` only while you have other work; finish with `bash_watch`):

| Command | `runon` | Purpose |
|---|---|---|
| `bash scripts/prepush/fast-compile.sh` | `linux,4c,net` | Mandatory fast feature matrix + Windows target compiles + workflow regression guards |
| `bash scripts/prepush/linux-rust.sh` | `linux,16c,net` | Full CI Rust inventory, 3 unit + 3 integration shards, watcher/conformance, Landlock, storm, MSRV |
| `bash scripts/prepush/linux-typescript.sh` | `linux,16c,net` | Unit/plugin E2E, Pi RPC, Docker/OpenCode 2, conditional beta-pin matrix |
| `bash scripts/prepush/linux-search.sh` | `linux,16c,net` | Pinned search-quality provisioning and mode-selected gate |
| `bash scripts/prepush/windows.sh` | `windows` | Native nextest (6 unit + 3 integration shards), watcher/conformance, deny-warnings and native E2E |
| `bash scripts/prepush/macos.sh` | `macos` | Four-core native sandbox/TLS/backtrace, watcher/conformance and macOS E2E |

For example: `bash({command: "git log -1; bash scripts/prepush/linux-rust.sh", runon: "linux,16c,net", background: true, timeout: 2700000})`. Launch the other lanes the same way. If a Windows transport omits Git metadata, prefix its command with `PREPUSH_COMMIT=` and the full snapshot SHA from your local `git rev-parse HEAD`; the lane requires and records that caller-reported value but cannot verify it against the copied files. Separate Linux jobs may queue behind the same workspace's active job; do not run Cargo and plugin E2E against the same checkout concurrently. Each lane saves full output under `.cortexkit/internal-docs/investigations/prepush/` and prints a short verdict. Use `return_paths` for the lane log when available; copy evidence out of build directories before delivery.

Requirements: stable Rust, cargo-nextest (CI pins 0.9.138), Bun, Node 24, Python 3, and network for dependencies. Linux needs zstd, ripgrep, Docker, real rust-analyzer, a Landlock-capable kernel/syscall policy and Rust 1.92 for MSRV. Windows needs MSVC, Git Bash, PowerShell and Python 3.14+ (`python` and `python3` on PATH) for archive probes/inventory. Local fast checks and the search lane need `origin/main` history; set `PREPUSH_BASE` to the pinned base SHA if necessary. Fast publication checks also need tag `v0.48.1`. Never silently skip a missing prerequisite. Some commit-attribution checks require GitHub PR or queue events; design approval and queue-member API checks remain hosted. The macOS lane covers selected native checks, not the complete macOS CI suite. Details: `.cortexkit/internal-docs/investigations/ci-parity-audit.md`. The nightly cost benchmark does not gate pull requests or the merge queue.

## Approvals and file fence

**Standing approval; do not ask:**
- Regenerate schemas, catalog presets, parity fixtures and Rich UI samples with their generators when the difference is caused only by your change.
- Merge `origin/main`; resolve conflicts keeping both sides' intended behavior.
- Add a non-ranking search descriptor for fenced-file changes that do not change ranking.
- Add test-only seams; widen a wait only with measured timing evidence and every assertion retained.
- Vendor upstream contract fixtures byte for byte with provenance.
- Fix path-form mismatches at the comparison site.
- Write a one-line release-note fragment under `.alfonso/release-notes/next/` for user-visible changes only.

**Always ask first; propose the exact text or change:** agent-visible text (including refusals and warnings); tool arguments or config keys; storage formats or migration numbers; security or permission boundaries; deleting or weakening a test; anything outside your assigned file fence. Standing approval does not expand the file fence.

## Rust (`crates/aft`, package `agent-file-tools`)

| Gate | Command | Proof it ran |
|---|---|---|
| Format | `cargo fmt --all -- --check` | Silent on success. Show `cargo fmt --version` and exit 0. |
| Windows compile | `RUSTFLAGS="-D warnings -A deprecated" cargo check -p agent-file-tools --tests --target x86_64-pc-windows-gnu` | `Finished` line. Compile-only: it cannot catch Windows runtime failures. |
| Unit (lib) | `cargo test -p agent-file-tools --lib -- <filter>` | `test result: ok. N passed` with N > 0. A filter that matches nothing reports `0 passed`, which is not a pass. |
| Binary tests | `cargo test -p agent-file-tools --bin aft -- <filter>` | Same as above. Shared infrastructure (locks, leases, capability gates, path identity) breaks fixtures here too. |
| Integration | `cargo test -p agent-file-tools --test integration -- <filter>` | Same as above. |
| Windows native tests | `bash scripts/windows-gate.sh --filter <filter>` or `cargo test -p agent-file-tools --lib -- <filter>` | Run with `runon: "windows"`. The Windows job snapshots tracked and untracked files, but not ignored files. A gate filter that runs zero tests fails. |
| Other test targets | `--test engine`, `--test list_envelope`, `--test rest`, `--test semantic`, `--test alert`, `--test watcher_integration` | Same as above. |
| Real rust-analyzer | prefix with `AFT_TEST_REQUIRE_RUST_ANALYZER=1` | Without it, real-server tests skip silently. |
| Full suite | `cargo test -p agent-file-tools`, or `scripts/rust-test-gate.sh` | The gate prints `GATE PASSED` / `GATE FAILED` as its last line. |

### Build server jobs (`runon`)

- **Never build or test on the user's Mac, except the prescribed source-only local fast phase.** Native compiles, builds and test suites run on servers. Use `linux,16c` for the full Linux lanes, `linux,2c` for a filtered test binary and `linux,4c` for fast-compile or a crate check. macOS servers have four vCPUs. If a full allocation is refused for capacity, retry rather than moving it locally. Filtered jobs can shrink to `linux,1c`. If an earlier job holds the workspace, wait for it or stop it only if it is yours and no longer needed.
- **Commit first, then submit, in separate steps.** The job snapshots the checkout when it is accepted. A commit sent in the same parallel step can land after the snapshot. Print `git log -1` as the job's first line so the output shows what ran.
- **Keep gate scripts out of ignored paths.** The job copies tracked and untracked files, but not ignored ones, so a script under `.cortexkit/` or `target/` is missing on the server.
- **Write long output to a file inside the job and print a summary.** A job that streams tens of megabytes back can lose its connection and come back with an unknown result.

Mandatory when you touch them:
- A list-cutting site (`.take(`, `truncate(`, a cap): register it, then run `cargo test -p agent-file-tools --test list_envelope`.
- A new file under the search engine: register its owner, then run `cargo test -p agent-file-tools --test engine`.
- An agent tool argument: regenerate with `bun run --cwd packages/opencode-plugin build:tool-schemas`. The committed `crates/aft/src/subc_tool_schemas.json` must match byte for byte.
- Config keys or the resolver: run `bun scripts/capture-config-parity.ts` (zero diff), then `cargo test -p agent-file-tools --test integration config_parity`.
- Search ranking or routing files (the `RANKING_FENCE_PREFIXES` in `benchmarks/aft-search/search_quality_lib.py`): say so in your report. The train needs a search-quality descriptor, and ranking changes need benchmark evidence.

## TypeScript (`packages/*`)

Build the bridge first whenever you change it: `bun run --cwd packages/aft-bridge build`. The plugins import its `dist/`. A stale `dist/` gives "export not found" or "property does not exist" errors that look like your bug.

| Gate | Command | Proof it ran |
|---|---|---|
| Lint (Biome 2.x) | `bun run lint` at the repo root | `Checked N files`. Show `./node_modules/.bin/biome --version`. |
| Typecheck | `bun run --cwd packages/<pkg> typecheck` | Exit 0. Name the package. |
| Unit tests | `bun run --cwd packages/<pkg> test:unit` | `N pass` / `0 fail` with N > 0. |
| End-to-end tests | `bun run --cwd packages/opencode-plugin test:e2e` (and pi-plugin) | Same as above. They spawn `target/debug/aft`. |

New test files go under `src/__tests__/`. A guard fails the suite on any test file elsewhere.

## Generated artifacts / byte-drift checks

Regenerate only with the named generator; do not hand-edit artifacts. Local fast checks JS outputs/config fixtures byte for byte and restores write-only generator output. `native-drift.sh` in the Linux Rust lane checks native outputs; zero matching tests is a failure.

| Artifact | Regenerate | Check |
|---|---|---|
| Subc/remote schemas and JS presets | `bun run --cwd packages/opencode-plugin build:tool-schemas` | Local `--check-source-only`; server `bun packages/opencode-plugin/scripts/build-tool-schemas.ts --check` also checks native hashline bytes |
| Catalog replies and preset fixture | `cargo test -p agent-file-tools --lib regenerate_tool_provider_catalog --locked -- --ignored` | Server `native-drift.sh` regenerates both catalog JSON files, byte-compares and restores them |
| Config parity fixtures | `bun scripts/capture-config-parity.ts` | Local `generated.sh` regenerates, byte-compares and restores; Rust integration verifies resolver parity |
| Rich UI carrier samples | `cargo test -p agent-file-tools --lib capture_carrier_samples -- --ignored` | `cargo test -p agent-file-tools --lib -- carrier_samples_match_wire` |
| Rich UI handler manifest `crates/aft/tests/fixtures/rich_ui/aft-rich-ui-manifest-v1.json` | `cargo test -p agent-file-tools --lib -- regenerate_rich_ui_samples --ignored --nocapture` | `cargo test -p agent-file-tools --lib -- rich_ui_samples` (server drift lane) |

All worker guidance belongs in `.cortexkit/WORKER.md`, not a separate root guide.

## Do not
- **Pipe a gated command** (`cmd | tail`, `cmd | grep`). The pipe's exit code hides the failure. Run it bare, or save output to a file and read the file.
- **Run TypeScript end-to-end suites while cargo is building** the same checkout. Cargo rewrites `target/debug/aft` mid-run and every bridge test fails with "Bridge shutting down".
- **Run the plugin end-to-end or permission suites from a worktree under `/tmp`.** The temp-directory permission exemption makes their assertions wrong.
- **Generate synthetic CPU load** (busy loops, stress tools). To test timing under load, use the injected-delay test hooks (`test-timing-hooks`) or a narrower deadline.
- **Run `aft_inspect` on Rust files while your own build or tests are compiling.** Its rust-analyzer check can hold the target lock.
- **Send a `read` in the same step as the bash command whose effect it checks** (for example a `git checkout --` revert). Parallel calls race, and the read can finish first and show the old file. Read in the next step.
- **Write closing keywords** (`Fixes #N`, `Closes #N`, `Resolves #N`) in commit messages. Write `(#N)`.
- **Write scratch files to `/tmp` or `$TMPDIR`** (diffs, logs, extracted outputs). Reading them back raises a permission ask your head has to answer. Keep scratch under `target/` in your worktree, which is git-ignored and readable without asking.
- **Edit `ARCHITECTURE.md` or `STRUCTURE.md`** to log a change.

## Before you report
- Publication source changes do not need generated docs or alignment commits.
  Run `node scripts/release-gate-v049.mjs --check-inputs` after committing the
  source (requires the `v0.48.1` tag and the built bridge). Run it in your
  worktree, not with `runon`: build-server snapshots carry no git tags, so it
  always fails there. It prints six staged
  transitions and `release gates passed`; it never runs a native build.
  The reviewed legacy-vocabulary allowlist remains an input: update it explicitly
  only when intentionally changing a reviewed occurrence, never in preflight.
  Release snapshots are automatically prepared and validated by `release.sh`
  and the publish workflow, outside Git. To validate a saved snapshot without
  regenerating it: `node scripts/release-gate-v049.mjs --snapshot-dir <dir> --candidate`.
- Run the local fast phase and every full server lane, in addition to focused regression tests needed during development. For a bug fix, add a regression that would fail without the fix. Do not weaken assertions to make a gate green. Repeated timing runs need a purpose and recorded measurements, not a claim that a flaky test is stable because it passed twice.
- If a gate could not run, say which one and why. Do not report it as passed.
