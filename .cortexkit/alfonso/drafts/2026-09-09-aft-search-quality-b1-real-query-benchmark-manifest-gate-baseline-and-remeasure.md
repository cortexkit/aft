## intent

B1 is the benchmark half of the search-quality split: it owns the real-query manifest, reproducible offline inputs, quality-gate families, the frozen B0 reference, CI wiring, and the post-release re-measure. It owns no router, lane plan, embedding counter, token variant, readiness behavior, ranking engine, paging implementation, or confidence implementation. The census observed 89,202 OpenCode `aft_search` calls (`.alfonso/data/aft-search-followup-census/summary.md:5-8`); pass 2 identified 6,469 discriminating episodes and projected 3,996 true search failures, or 19.80% of 20,183 `aft_search` to grep-family episodes (`.alfonso/data/aft-search-followup-census/mechanism-report.md:11-21`). B1 turns those real episodes into a deterministic file-rank benchmark, freezes B0 on main before campaign A's first ranking slice and before any B2 slice merges, gates A and B2 against that reference, and later repeats the failure-rate estimate without treating file rank as a failure label.

### Identity, manifest, replay, and authoring

- **Canonical identity (R29).** The source files call their integer key `episode_number`. Authoring converts it once to the canonical string `episode_id = "followup-census:<base-10 episode_number>"`. Manifest rows, exclusions, score rows, samples, fixture lists, reports, diagnostics, and tests use only `episode_id`; `episode_number` exists only in the read-only census inputs and in the conversion rule. Sorting by episode identity means sorting by the integer suffix, not lexicographically. One episode selected both as a fixed mechanism fixture and by the stratified sample produces one manifest row with `dual_source: true`.
- **Manifest row schema (R10/R31).** `benchmarks/aft-search/real-query-manifest.json` has one included or excluded row per selected identity. Every included row carries: `episode_id`; `repo`; immutable repo `sha`; `query`; `census_stratum`; `pinned_shape`; `mechanism`; `opened_file`; `include_tests`; `include_tests_source`; `recorded_top_k`; `confidence_split`; `dual_source`; corpus `bundle` path and SHA-256; embedding-pack path and SHA-256 when required; `pruning_policy_id`; `competitor_count`; and `policy_excluded_competitor_count`. `include_tests` is boolean and `include_tests_source` is exactly `recorded | default`. Exclusion rows retain all known provenance and their reason; only an `include_tests_indeterminate` exclusion omits the unknowable `include_tests` pair. The raw census demonstrates that the value is episode-specific, including explicit `true` rows (`mechanisms.jsonl:1-3`) and explicit `false` rows whose acted-on file is test support (`mechanisms.jsonl:682,1181`).
- **Recorded `includeTests` is replayed, never global (R31).** If the captured tool input explicitly contains `includeTests`, authoring records that boolean with source `recorded`. If the captured input omits the field, authoring records `false` with source `default`, matching the pinned Pi schema (`packages/pi-plugin/src/tools/semantic.ts:48-61`) and backend serde default (`crates/aft/src/commands/semantic_search/mod.rs:186-195`). Replay always forwards the manifest boolean explicitly as public `includeTests`; it does not rely on the runtime default. If the original value cannot be determined and the opened file is in the surface's excluded test-support classes, the row is excluded as `include_tests_indeterminate`; other indeterminate rows are an authoring error until provenance is recovered. A request-recorder mismatch is P1 `replay_input_mismatch` and names the identity, expected value/source, and sent value.
- **Explicit exclusion reasons.** The closed reason set is `repo_unowned_or_unavailable`, `opened_file_absent_at_sha`, `worktree_only_path`, `label_not_bundle_eligible`, and `include_tests_indeterminate`. Exclusion rows keep their `episode_id` and provenance and are included in the exclusion table. No other omission is legal.
- **Scored population is set equality, not count equality (R29).** Before any metric is computed, the gate rejects duplicate `episode_id`s in either manifest or score file. It then requires the de-duplicated score-file identity set to equal exactly the manifest's non-excluded identity set. Any duplicate, foreign, or missing identity is P1 `scored_population_mismatch`; diagnostics print the three offending-id sets. `declared_total` and exclusion counts may be reported for humans but never establish validity. Replacing one scored row with a second copy of another row therefore exits 2 before metrics even though the row count is unchanged.
- **Stratified sample.** The fixed mechanism fixtures above are unioned with a seeded sample whose retained target is 200 rows (the sibling A hand-off describes the same 200-row family at `.cortexkit/alfonso/drafts/2026-09-09-aft-search-ranking-engine-a-comparator-exact-lane-anchored-fusion-paging-confidence-refire-1.md:33-38`). Eligible identities are grouped by the five `census_stratum` values, sorted by numeric identity suffix, and sampled with `random.Random(20260908)` (seed source: `mechanism-report.md:3-9`). Largest-remainder allocation from the exact census counts in `mechanism-report.md:25-31` gives the checked-in initial quota vector `{identifier: 62, code_literal: 53, short: 25, nl: 56, log_excerpt: 4}`. Ties use stratum name ascending.
- **Quota totality (R23).** An empty stratum records weight `0`, quota `0`, and `reason: zero_population` and is omitted from the positive-weight denominator. An under-populated stratum contributes all eligible identities; its deficit is redistributed one identity at a time in descending renormalized weight, ties by stratum name. If fewer than the target are eligible, the sample is the entire eligible population and `shortfall_total` records the gap. If all strata are empty, allocation is skipped, `weight_denominator: 0`, every quota is `0`, and no `null`, `NaN`, or infinity is serialized. `quota_plan` records source counts/shares, eligible counts, initial/final quotas, deficits, redistributed rows, denominator, shortfall, seed, and source-artifact digests.
- **Confidence partition is defined, not implied.** B1 records `confidence_split` from the canonical identity's integer suffix: even is `calibration`, odd is `evaluation`. The A-owned calibration chooses the threshold and evaluates `precision(high) - precision(low) >= 0.15` with support at least 50 in each class, exactly as pinned in the A sibling (`.cortexkit/alfonso/drafts/2026-09-09-aft-search-ranking-engine-a-comparator-exact-lane-anchored-fusion-paging-confidence-refire-1.md:104-115`). B1 supplies the deterministic partition and report table only; A owns confidence behavior and its gate.
- **Corpus honesty.** Bundles are generated at `(repo, sha)` by `pruning_policy_id: v1`, which drops only `.git/`, `target/`, `node_modules/`, `dist/`, `build/`, files larger than 2 MiB, and non-UTF-8 files. The pruner receives neither query, label, opened file, nor score. `competitor_count` counts policy-eligible non-label files whose trigrams cover every query token of at least three characters; matching files removed by policy contribute only to `policy_excluded_competitor_count`. A policy-excluded label becomes `label_not_bundle_eligible`. Goldens cover label blindness, decoy retention, and a mixed tree; pruning to the label or to index-buildable files must red.
- **Checked-in-only gate inputs.** CI consumes only `real-query-manifest.json`, `manifest.sha256`, the reference, the two campaign pins, the ruling index, label table, bundles, embedding packs, and binary goldens under `benchmarks/aft-search/**`. `.alfonso/data/**`, reflogs, credentials, and network are authoring-only and forbidden in verify/evaluate. Existing benchmark code already treats the in-tree fixtures as file-path labels (`benchmarks/aft-search/README.md:28-49`) and defines retrieval metrics separately (`README.md:127-147`); B1 extends that harness rather than replacing those definitions.
- **Offline embeddings without B2 product changes.** A benchmark-local fixture HTTP server under `benchmarks/aft-search/**` serves the checked-in vectors through the existing configurable embedding endpoint. It binds loopback only, rejects unknown corpus/query keys, and logs every request. The network sandbox denies every non-loopback connection. A missing vector is P1, never a zero vector or skipped row. This keeps B0 independent of B2's future embedding counters and leaves `semantic_index.rs`, `embed/**`, and the production provider selection untouched.

### Gate families, schemas, and predicate

- **Existing entry point and families.** `scripts/telemetry/cost-gate.sh` remains authoritative. At the pinned SHA it has an explicit `--exact-recall` branch to `run_exact_recall.py` and otherwise dispatches to the index-cost gate (`scripts/telemetry/cost-gate.sh:1-14`). B1 preserves both and adds `--concept-recall`, `--real-query`, and the aggregate `--search-quality`; `index-cost` remains outside the quality predicate. The quality job runs imports-resolve, exact-recall, concept-recall over `fixtures.json`, then real-query over the manifest.
- **Metrics are unchanged.** Each family reports `MRR@10`, `hit@1`, and `hit@5`; real-query reports those metrics as unweighted row means at family, `pinned_shape`, and mechanism levels. File rank is the first distinct collapsed path equal to `opened_file`; repeated symbols from one path occupy one file position. A label absent from the first ten distinct paths scores zero. A census-share-weighted MRR is printed but never gates.
- **Execution modes (R25).** `--search-quality` accepts exactly `evaluate`, `record-reference`, and `verify`:
  - `evaluate` is the default slice gate. It requires a valid descriptor and reference, requires the reference profile unless the exact rebaseline transaction below is requested, and evaluates P1/P2/P3.
  - `record-reference` is B0-only, accepts no descriptor, computes no delta, requires resolver/input/offline-provider goldens, and atomically writes the initial `real-query-baseline.json` plus `manifest.sha256`. Its only statuses are 0 and 2.
  - `verify` accepts no descriptor, computes no delta, writes no reference, validates every input, and runs all three quality families to completion with network disabled. Its only statuses are 0 and 2.
- **Descriptor.** Every ordinary evaluate run declares `slice_class: ranking | non_ranking`. A ranking slice names a manifest mechanism with at least one scored identity. A non-ranking slice sets `targeted_mechanism: none` and names `kind: readiness | paging | confidence | harness`, with at least one declared binary fixture of that kind and one result for every declared fixture. B1's own infrastructure slices use `non_ranking`, `none`, and `harness`; they never claim a ranking improvement.
- **Score-file validity.** A score file records schema, model id, retrieval profile, capability declaration source, baseline path/digest, the scored rows with unique `episode_id`, family/group/shape/mechanism aggregates, and all declared binary-fixture results. Every required metric is present, finite, and in range. Every manifest shape represented in the reference has a score block. Every real-query row has `pages_fetched`, `collapse_stop_reason`, the manifest `include_tests` and source, and the actual replay request. R29 set equality and R31 replay equality are checked before aggregation.
- **Shared floor (R13).** Exact-recall and concept-recall are flat-or-up on every metric at family and fixture-group levels. Real-query aggregate MRR@10 is flat-or-up; each represented `pinned_shape` may lose at most 0.01 absolute MRR@10 and may not lose hit@5. This is identical for ranking and non-ranking slices. A ranking slice additionally requires strictly higher targeted-mechanism MRR@10 and non-decreasing targeted-mechanism hit@5. A non-ranking slice additionally requires all binary fixtures of its kind to pass and has no extra ranking requirement.
- **Total ordered predicate (R5/R6).** P1 wins and exits 2 on any input/harness fault: malformed schema or descriptor; resolver/pin/digest failure; missing reference; illegal profile; corpus/vector/model mismatch; non-loopback network attempt; `replay_input_mismatch`; `scored_population_mismatch`; duplicate identity; non-finite/missing metric; undeclared/missing shape or mechanism block; missing row stop fields; request-bound violation; inconsistent capability declaration/probe; or rebaseline precondition/transaction failure. Otherwise P2 exits 1 and prints every quality-floor, targeted-mechanism, or binary-fixture failure. Otherwise P3 exits 0. A generated truth table covers all named axes and combined-failure precedence; the numbered acceptance goldens are examples, not a partition.

### Retrieval profiles and rebaseline

- **Capability is a schema declaration (R22).** The harness reads each surface's published request schema and sets `offset_declared: true` iff the schema's `properties` explicitly declares `offset` with its bounds. It records schema path and SHA-256. Unknown-property tolerance and the absence of a validation error are never evidence. At the pinned SHA the Pi schema declares `query`, `topK`, `includeTests`, and `path`, but no `offset` (`packages/pi-plugin/src/tools/semantic.ts:42-69`); `topK` is bounded to 100 there (`semantic.ts:48-54`).
- **Behavior probe.** Only when `offset_declared` is true, the harness requests a fixture page at offsets 0 and 100 and requires different first rows, recording `probe_pages_differ: true`. A declared but ignored offset is P1. If offset is undeclared, the harness sends no offset-bearing request and no behavior probe.
- **`single_page`.** Exactly one public request per row at `topK: 100`, with no `offset`; its tuple budget is 100. Returned tuples collapse to paths in order and stop at ten distinct paths, exhaustion, depth cap, or page end. No live single-page test may simulate continuation by repeating the first page.
- **`paged`.** Available only when the schema declares offset and the behavior probe passes. Normal scoring uses public `topK: 100` requests at offsets 0, 100, 200, and 300 under one generation, with a 400-tuple budget and the same collapse rules. Every request respects the published topK/offset bounds and the harness never calls A's internal reference retrieval.
- **Stop and score fields.** `collapse_stop_reason` is exactly `ten_files | exhausted | depth_cap | page_cap`; reaching any stop is an ordinary score outcome. A stability-void response is scored from tuples already fetched and marked in the report.
- **Page-size invariance is legal.** Live multi-request invariance runs only after `paged` is available. Over the first 100 legally fetched tuples it compares page size 10 at offsets 0 through 90 (10 requests), page size 25 at offsets 0/25/50/75 (4 requests), and page size 100 at offset 0 (1 request). Completing rows must have byte-identical collapsed paths, per-row metrics, and aggregates. The `single_page` companion makes its one legal `topK: 100` request once and tests only harness-side partitioning of that already-fetched tuple vector; it issues no additional public request. Rows that hit page/depth cap are excluded from invariance and covered by literal per-budget goldens.
- **Budget goldens.** A tuple stream with repeated symbols from `wrong.rs` before `opened.rs` proves path collapse. A deep-collapse stream whose label starts after the single-page budget scores zero with `page_cap` under single-page and non-zero at its literal collapsed rank under paged. Any non-zero single-page score must be identical under paged; the converse is not required.
- **Reference identity and ordinary mismatch.** A baseline records model id, profile, capability block, manifest digest, and score set. Ordinary evaluate under a profile different from the reference is P1 and writes nothing.
- **The only rebaseline invocation.** A profile transition is allowed only by these commands, in this order, on the same clean HEAD:

  `scripts/telemetry/cost-gate.sh --search-quality --mode verify`

  `scripts/telemetry/cost-gate.sh --search-quality --mode evaluate --rebaseline --from-profile single_page --to-profile paged --descriptor <non-ranking-harness-descriptor.json>`

  The second command verifies a receipt from the first command matching HEAD, manifest digest, old reference digest, and model id; requires explicit from/to values exactly as shown; requires declared-and-working offset; runs full P1 and binary profile goldens; and requires the new de-duplicated `episode_id` set to equal the old reference set exactly. It prints old/new reference SHA-256, old/new profile, both capability blocks, and the full metric delta.
- **Atomic pair update.** Rebaseline writes sibling temporary files for `benchmarks/aft-search/real-query-baseline.json` and `benchmarks/aft-search/manifest.sha256`, validates and fsyncs both, then commits them through the transaction helper so both new files become visible or the old pair is restored. Any validation, write, fsync, rename, or rollback failure exits 2, leaves/reinstates the old pair, prints the failed stage, and never reports success. A fault injected between the two renames proves that both checked-in paths retain their old bytes. `real-query-manifest.json` is unchanged by rebaseline; `manifest.sha256` is the digest sidecar that binds both manifest and reference digests.

### Post-release re-measure

- **Purpose and population (R26).** `scripts/telemetry/postA-remeasure.sh` is offline, never runs in CI, and is never read by `cost-gate.sh`. It extracts the release-date through release-date-plus-90-day window from the same census stores, uses the five `census_stratum` values and `c_s` table above, sorts by canonical `episode_id`, and samples 300 labels with `random.Random(20260908)` (the retained census sample/seed source is `mechanism-report.md:3-9`). It uses `benchmarks/aft-search/failure-rubric-v1.md`, transcribed from the original protocol; a missing rubric exits 2 before any output.
- **Estimator.** For stratum `s`, `n_s` is its labelled sample count and `f_s` its true-failure count. For `n_s > 0`, `p_s = f_s / n_s`; normalize census shares only over sampled strata, `w_s = c_s / SUM(c_t where n_t > 0)`, and compute `p_w = SUM(w_s * p_s)`. Empty-stratum census mass is dropped and recorded as `dropped_census_mass_remeasure`. `labelled_total = SUM n_s`.
- **Interval arithmetic.** For a non-empty population, `n_eff = 1 / SUM(w_s^2 / n_s)` over sampled strata only. The weighted 95% Wilson interval uses `z = 1.959964`, unrounded binary64 `p_w` and `n_eff`, then records point, endpoints, rounded and unrounded effective size with half-even six-decimal serialization. The unweighted rate `SUM f_s / SUM n_s` gets the same Wilson calculation at the integer labelled total. A zero or one point estimate is ordinary and produces finite clamped endpoints.
- **Outputs and separation (R27).** The script writes exactly: (a) `followup-remeasure-<release-date>.md`, a prose label-side report; (b) `followup-remeasure-<release-date>.json`, the estimator artifact; and (c) `real-query-postA.json`, ranking metrics plus retrieval profile only. For a non-empty run, the report and estimator carry rubric path/digest, population/window/seed, all five stratum rows, `labelled_total`, dropped mass, weighted and unweighted estimates/intervals, effective sample size, and containment verdict. `real-query-postA.json` carries none of those label, rubric, or estimator keys and is never a baseline.
- **Partially empty rows.** A non-empty estimator includes one row for every census stratum. Every row has `census_stratum`, `c_s`, `n_s`, `f_s`, and `sampled`. A sampled row also has finite `p_s` and `w_s`; an unsampled row has no `p_s`, has numeric `w_s: 0`, and has `reason: no_labelled_episodes`. Undefined rates are never read.
- **All-empty artifact is exact (R30).** If `labelled_total == 0`, the estimator JSON has exactly three top-level keys and no others:

  `{"labelled_total":0,"population":<the pinned population descriptor>,"estimator":"undefined_empty_population"}`

  `population` is the same descriptor used by non-empty runs and contains the census artifact digests, five-stratum identity, window bounds, and seed. Every undefined field is absent: weighted point, rounded/unrounded effective sample size, unweighted rate, dropped mass, stratum rows, rubric fields, containment verdict, and all interval keys. No undefined field is serialized as zero, null, or NaN. The prose report still names the population and rubric and prints `no labelled episodes; no interval computed`. The empty fixture compares the complete key set and values byte-for-byte; any extra or missing key fails.
- **Comparison.** The report prints whether each computed interval contains the original point `0.198`, whose source is the projected 19.80% result in `mechanism-report.md:15-21`. It explicitly says this is containment of a prior point estimate, not a significance test or an improvement claim. Empty runs print no containment line.
