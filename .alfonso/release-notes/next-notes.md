# Notes for the next release

- Disk retention: finished bash tasks release scratch directories once their process groups exit, older terminal scratch folders are swept, and vanished-checkout views drain in bounded consecutive passes with a visible backlog count.
- 0.60.1: Worker file tools can read Cargo registry sources and Rust toolchains without permission cards; writes, credential/cache paths, permanent deny floors, and shell confinement are unchanged.
- Basal exact reads: an AFT tool-provider route bound by Basal under a short-lived `flow-read/` child of a live head scope can call `file.read_exact` for one file in the head's project, under the head's permissions, and gets the file's bytes, size and SHA-256. Such routes cannot call any other tool or grant operation, and management routes refuse them.
- Permissions: grep, outline, zoom, callgraph, AST search, inspect and OpenCode glob now recognize exact session-owned bash output without OpenCode's external-directory prompts or Pi's root-restriction denials; directory-wide searches, other sessions' output and mutations stay protected.
- Daemon stability: source scans for search, code navigation, inspection, and file watching now skip AFT's internal task/cache directories and SQLite databases plus their WAL/shared-memory/journal files, avoiding lost SQLite locks and SIGBUS crashes. Source folders with database-like names remain searchable, and committed database fixtures no longer break view builds. Explicit, authorized task-record reads remain available.
- Daemon health: scheduler contention now preserves the last measured census and timestamp, marks it stale with an increasing age, and reports unmeasured startup metrics as null instead of empty/zero/available. The health sentinel treats stale or unknown census data as an instrument failure without losing watcher baselines or disabling live liveness checks.
- Bash compression: command lists with top-level separators (`cargo test && cargo clippy`, `git add . ; git commit`) now use generic compression instead of the head command's specialized compressor. Previously the specialized compressor silently deleted every later command's output from the response on success — 26.65% of real bash traffic (7-day sample) was affected. Chained commands are now more verbose but complete.
- aft_outline / aft_zoom: signature lines no longer carry the redundant visibility/kind prefix (`E fn `) — the signature text itself is the information. A minimal `E` marker remains only where exported-ness is not visible in the signature (e.g. TypeScript export lists, Go uppercase exports). ~5.5% mean output reduction on outline, compounding on zoom menus.
- apply_patch: updates no longer eat one terminal newline from files ending with two or more.
- Windows LSP: percent-escaped file URIs (paths with spaces, non-ASCII) now decode correctly, so diagnostics/goto/rename work on those paths.
- edit: empty-string mode sentinels sent by some hosts no longer reject valid edits[] calls (issue #171).
- Workflow hints ship inside the host's system entry — fixes "System message must be at the beginning" on Qwen-family endpoints (issue #150).
- Checkpoints under restrict_to_project_root now snapshot a symlink itself rather than its target.
- Callgraph stores sweep orphaned build temporaries (age-based, both layouts).
- OpenCode 2 now requires 2.0.29 or newer. Permission prompts run in-process through OpenCode's own permission check, including on standalone hosts and hosts without a readable server password, and edit prompts keep the built-in diff view. The `opencode.server_url` and `opencode.server_password_env` settings are removed; `npx @cortexkit/aft doctor --fix` deletes them.
- File watching no longer hangs on a project whose build folder is a link to an unresponsive or disconnected drive. Linked folders and folders on other drives are left out of watching without being opened.

## Sandbox profiles

- Replace the single stamped-worker shell jail with `sandbox.profile` role choices: `off`, `relaxed`, and `strict`. Stamped workers default to `relaxed`; heads, standalone and unstamped sessions default to `off`. Projects may only harden a profile; untrusted/MCP/unverified routes are always strict.
- macOS relaxed shells allow ordinary caches, sockets, browsers, toolchains and shared compile servers while protecting credentials, CortexKit private data, known sibling checkouts, shell/Git configuration and hook governance. Strict keeps the existing jail and sccache block. Short worker temp paths, GitHub CLI access checks, commit co-author attribution and child-environment stripping remain in place.
- Linux relaxed reports every deny as unenforced because Landlock cannot subtract paths from default-allow grants. Windows relaxed runs with an unenforced warning and a stripped child environment that preserves the process PATH and standard user variables; Windows strict refuses those launches. Seatbelt still cannot execute setuid `ps`/`top`; use `pgrep`/`pkill`, or select `off` when `ps` is required.
- Retire `sandbox.enabled` through the existing in-memory and `doctor --fix` JSONC migration: `true` maps to strict for both roles, `false` maps to relaxed worker/off head, and explicit canonical role values win. An absent setting uses the same new defaults; heads that explicitly enabled the old jail remain confined.
