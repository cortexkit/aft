# v0.58.0

AFT 0.58.0 replaces tool surface levels with one rule — a tool is on unless it is listed in `disabled_tools` — and turns every background index on by default, including semantic search. `aft setup` gains a feature wizard, `doctor --fix` migrates old configuration, and tools now say plainly when an index is off or still building. The plugins no longer run the `aft` binary on the host's thread at startup, daemon restarts recover faster and exit cleanly, and this release fixes the issues reported since 0.57.2. Read **Upgrading** at the end before you update: some configuration keys are retired, and one pair of old GitHub keys now stops AFT from loading until `doctor --fix` rewrites it.

## Feature-based configuration

`tool_surface` (`minimal` / `recommended` / `all`) and `hoist_builtin_tools` are gone. Every AFT tool is registered unless its name is in `disabled_tools`. There are no prefixed fallback registrations any more: `read`, `write`, `edit`, `apply_patch`, `grep`, `glob` and `bash` are either taken over by AFT or left to the host, and `aft_read`, `aft_edit` and the other prefixed names no longer exist. Disabling a host tool name leaves the host's own tool in place.

The new defaults: when your user config has no `disabled_tools`, AFT disables `aft_move` and `aft_delete` and registers everything else. That turns on `aft_callgraph`, `aft_search`, `grep` and `glob`, which the old `recommended` surface left out or only registered when an index was on. An explicit list replaces the default: `[]` enables every tool, and `["aft_search"]` disables only search. Names AFT does not recognise are kept and reported in one warning per load.

The three background indexes are now configured under `indexes`, and all three default to `true`:

| Setting | Replaces |
| --- | --- |
| `indexes.trigram` | `search_index`, `experimental_search_index` |
| `indexes.semantic` | `semantic_search`, `experimental_semantic_search` |
| `indexes.callgraph` | `callgraph_store` |

Each enabled index builds whether or not any tool that reads it is enabled, so disabling a tool no longer stops its index; set the index to `false` for that. A project config can turn an index off but cannot turn one on that the user config turned off. Project configs can also only add to `disabled_tools`, and never disable `aft_safety` or the seven host tool names, directly or through an old key; such attempts are ignored and logged.

Semantic search now defaults on with the local backend. The first time it runs, AFT may download an ONNX Runtime and the embedding model, and embedding a repository uses CPU. If semantic indexing is on only because of the new default (no semantic setting anywhere in your config and no remote backend), AFT shows this notice once per user config file, before any download starts: "AFT indexes now default on; the local semantic backend may download an ONNX runtime and model and use CPU. Run aft setup to change indexes.semantic; if legacy configuration is rejected, run aft doctor --fix first." It uses your `configure_warnings_delivery` setting. On a platform with no ONNX Runtime download and no other backend, semantic search reports unavailable with a named cause and AFT stops retrying the build on every reconfigure.

`backup.enabled: false`, `inspect.enabled: false` and `bash: false` now restrict what those features do at run time rather than whether their tools are registered. A registered tool whose feature is switched off answers `backup_disabled`, `inspect_disabled` or `bash_disabled`. Disabling only the `bash` tool name does not unregister `bash_status`, `bash_watch`, `bash_kill` or `bash_write`. With `edit_mode: "hashline"`, hashline needs both `read` and `edit`; if either is disabled, the remaining tool keeps its ordinary behaviour and AFT warns once per load (`hashline_read_disabled` or `hashline_edit_disabled`).

### `aft setup`

`npx @cortexkit/aft setup` now finishes with a checkbox wizard grouped into Search/navigation, Editing, Shell, Indexes and GitHub. It explains the cost of semantic indexing and what `aft_move` and `aft_delete` do. Rerun it, or run `doctor --reconfigure`, to change your choices. It writes only the user file `~/.config/cortexkit/aft.jsonc` and keeps its comments, formatting and unrelated keys. Setup always writes a complete `disabled_tools` list, including `[]`, and keeps names it does not recognise. For GitHub, ticking `github.write` also ticks and locks `github.read`, because writing implies reading. Setup saves only `github.write: true` in that case and leaves `github.read` unset.

For scripts and other tools, three modes skip the prompts:

- `aft setup --plan` prints the feature plan as JSON on stdout: every feature with its default, your configured value and where it came from, the effective state (`off`, `building`, `ready` or `unavailable`), the reason, and any cost note. Warnings go to stderr.
- `aft setup --answers <file|->` applies `{"plan_version":1,"selections":{"<feature-id>":true}}`. Features you leave out keep their current setting; an unknown feature ID or a non-boolean value fails without writing anything.
- `aft setup --yes` saves the proposed defaults, filling in only the settings your file does not have yet.

`--yes` and `--answers` cannot be combined. All three accept `--harness opencode|pi|omp` to show effective state for one harness and use the current directory to find the project config. `doctor` now lists every feature with the same states.

### Migrating an existing config

During 0.58, old keys are translated in memory on every load, and AFT shows one migration notice for each config file until the relevant contents change. From 0.59 the same keys are rejected with `removed_config_key:<old>:use:<replacement>`. `npx @cortexkit/aft doctor --fix` rewrites them now:

| Retired key | Replacement |
| --- | --- |
| `tool_surface`, `hoist_builtin_tools`, top-level `enabled` | `disabled_tools` |
| `search_index`, `experimental_search_index` | `indexes.trigram` |
| `semantic_search`, `experimental_semantic_search` | `indexes.semantic` |
| `callgraph_store` | `indexes.callgraph` |
| `github.enabled` | `github.read`, `github.write`, `github.shim` |
| `aft_read`, `aft_write`, `aft_edit`, `aft_apply_patch`, `aft_grep`, `aft_glob`, `aft_bash` inside `disabled_tools` | `read`, `write`, `edit`, `apply_patch`, `grep`, `glob`, `bash` |

How old values translate:

- An explicit `tool_surface` in your user config is treated as a complete choice. `"all"` becomes `[]`, `"recommended"` becomes `["aft_callgraph", "aft_delete", "aft_move"]`, and `"minimal"` disables everything except `aft_outline`, `aft_zoom` and `aft_safety`. Without one, the new `aft_move`/`aft_delete` default is combined with whatever the other old keys disable.
- `hoist_builtin_tools: false` disables the seven host tool names, so the host's own tools are used instead.
- Top-level `enabled: false` disables every tool, but **it no longer stops indexing**: the trigram, semantic and callgraph indexes still build, and the migration notice says so. To keep AFT from indexing a repository, also set all three `indexes.*` values to `false`.
- A false `backup.enabled`, `inspect.enabled` or `bash` still unregisters `aft_safety`, `aft_inspect` or the bash tools during 0.58 only, with a `legacy_runtime_gate_requires_fix` warning on every load. From 0.59, if not migrated, these settings only restrict run-time behaviour.
- An explicit `disabled_tools` in the same block, even `[]`, overrides everything the old keys would have disabled.
- `github.enabled: true` on its own now enables neither reading nor writing. `github.enabled: false` still turns read, write and the shim off, but only where you have not set `github.read`, `github.write` or `github.shim` yourself. An explicit value now wins over it, including `github.shim: true`.

`doctor --fix` rewrites the user config `~/.config/cortexkit/aft.jsonc` and the current project's `.cortexkit/aft.jsonc`, including every `harnesses.<id>` block inside them. It keeps comments and unrelated keys, writes each file atomically and reports each file's outcome. It does not touch the older per-harness files (`~/.config/opencode/aft.jsonc`, `~/.pi/agent/aft.json`, `<project>/.opencode/aft.jsonc`, `<project>/.pi/aft.jsonc` and their `.json`/`.jsonc` variants). AFT does not read those as configuration: they are only copied once into the shared location when it has no file yet.

## What tools report while an index is off or building

Every tool that reads an index now reports its state, so an index that is missing or still building is never presented as an empty result:

- `grep` and `glob` still answer by scanning the filesystem when the trigram index is not ready. The response now carries the trigram index state and marks a scan-based answer as `fallback: "filesystem"`.
- `aft_search` uses whichever of its trigram and semantic lanes are ready and labels the lanes it left out. When neither lane is ready it now refuses instead of falling back to a filesystem grep: `no_search_lanes_enabled` if both indexes are configured off, otherwise `search_lanes_unavailable`, with each lane's status and cause. A query also starts reloading an index that was evicted while idle.
- `aft_callgraph` refuses with `callgraph_off`, `callgraph_building` or `callgraph_unavailable`, including the index status and cause. With `indexes.callgraph: false`, a query no longer starts a build. Two older codes now use this shape: a suspended build reports `callgraph_unavailable` with cause `build_suspended`, and a home-directory root reports `callgraph_unavailable` with cause `home_root`.
- `aft_inspect` reports dead code as unavailable, with the callgraph status, instead of zero findings. The other analyses in the same request still run.
- `aft_zoom` with `callgraph: true` still returns the file's own `calls_out` and `called_by`, which never came from the index, and adds a `callgraph` field with the index status when the index is not ready.
- Search results say when callgraph enrichment was left out and why.

Checking index state never waits on a lock that index work holds, so a status query cannot hang behind a build.

## Plugin startup no longer runs the aft binary

Loading the OpenCode and Pi plugins could block the host's main thread: AFT ran `aft --version` on each candidate binary, hashed the ~85 MB binary, and copied it from the npm package into the cache, all synchronously. Downloads and cache installs now record a small identity file next to the binary, and startup trusts a cached binary whose identity file matches without running it. Anything that has to be run to be checked is probed on a worker thread, and the npm copy and hashing happen in the background. `AFT_BINARY_PATH` is still version-checked, off the main thread. When the plugin connects to the subconscious daemon (`subc.connection_file`), it resolves no local binary at all. If an identity file is wrong about the version, the existing version check on connection still catches it.

## Daemon restarts and health (subconscious daemon users)

- **Binds after a restart.** When the daemon restarted, every session rebinding at once could keep new sessions from getting a worker in time, and they were refused with "did not answer route.bind within 12s". Two workers are now reserved for route binds and run nothing else. A pending bind pauses new reads on its project after 500 ms instead of 6 s, and the post-bind catch-up for each project gives way to a waiting bind. That catch-up is paced across projects: at most four run at once and four start per 250 ms tick. The first code-health refresh for each project is spread out rather than all firing 90 s after the restart.
- **Drains finish.** A restart drain waited its full 30 seconds whenever the daemon still held a request AFT had stopped tracking: streams on a deleted project that AFT reclaimed, or a call the client cancelled. Those now get a final reply. A cancelled `wait: true` bash call is answered at once instead of when its command exits. During a drain, bash calls that have not detached on their own are answered within 500 ms and moved to background tasks, so their commands keep running and their completions are still delivered.
- **Exit codes.** When the daemon closes the connection after telling AFT it is draining, AFT now exits 0 and logs that the stop was requested. It used to exit 1 with no log line, which the supervisor recorded as a crash. A connection lost without that notice still exits 3. Log lines written just before exit are no longer lost: AFT waits up to 2 s for the log file to catch up.
- **Stalls.** A watchdog now notices when the module's frame loop or dispatch loop has owed work for 15 s without progress. It logs the start and end of each stall and captures evidence: a `sample` of the process on macOS, or every thread's state on Linux, written to `<storage>/diagnostics/stall-*.txt`. It captures at most once per 10 minutes and keeps the newest five files. `health.check` reports stall counts under `dispatch_path.stall_watchdog`, along with the captures.
- **Bind latency.** `health.check` reports `dispatch_path.bind_acks`: over the last five minutes, how many binds were answered, how many took longer than 5 s, and the slowest. Lifetime totals are included. The daemon refuses binds that take more than 12 s, so a rising slow count gives warning before that happens.
- **Abandoned projects.** A project that stays unbound for more than two minutes has its semantic and callgraph cold builds stopped at their next checkpoint. The work already saved is kept, so a later bind resumes from it. A restart that rebinds within the window is unaffected.
- **Frame loop stalls behind background bash.** A `wait: true` bash call checked its task on the thread that serves every session's requests, and that check could wait on a task lock held while the task's record was written to the database. After a restart, when every session's cleanup queued on that database at once, the whole module stopped answering for 25 s. The check now runs off that thread, task records are written after the task lock is released, and one cleanup pass per storage root serves every project instead of one per project.
- **Plugin connection drops.** The plugin closed its whole connection to the daemon, taking down every session on that host, after three failed requests in a row from any sessions combined. Under restart load, three slow requests were enough, and every session then reconnected at once. Now only evidence of a dead socket closes the connection; a run of failed requests triggers a quick liveness check on the same connection first. Each drop is logged with its cause and how many sessions it affected.
- **Watcher exclusions after a restart.** A project rebound after a restart could start its file watcher with only `.git` excluded, because the step that loads its ignore rules had been cancelled; a Rust or Node build then overflowed the watcher. The ignore rules now load as background work when a watcher is restored without them, and the watcher updates its exclusions when they arrive. The exclusions log line says `matcher=unloaded` while the rules are not loaded yet.
- **Idle projects held in memory.** A project whose session ended right after a file change kept its search index in memory until the daemon restarted, because the unsaved change blocked cleanup and nothing saved it. The change is now saved when the idle timeout passes, then the memory is freed. `health.check` counts projects held past their timeout, with the reason. (#356, reported by @iceteaSA)

## gh shim

- The target repository now decides the bot identity. The shim used to take it only from the working directory's `origin`, so a governed command aimed at a bound repository with `-R`/`--repo`, a thread URL or `GH_REPO` ran as the operator whenever it was issued outside that repository's checkout. The shim now resolves the target the way `gh` does: `--repo`, then a URL or API endpoint in the arguments, then `GH_REPO`, then the checkout. A governed request whose target does not match the bound repository is refused, as is a thread URL that disagrees with `--repo`. Commit co-author lines still follow the checkout.
- New operator rows for labels: `issue edit` and `pr edit` with only `--add-label`/`--remove-label`, and `label create`, run under `GH_SHIM_BYPASS=operator` with an audit line. Any other argument is refused by name. These rows take effect only once a signed routing manifest at version 14 or later is active; under the currently deployed version 13 manifest they are still refused as unclassified. See `docs/gh-shim.md`.
- Governed bot writes now go through the AFT daemon to the plexus GitHub service instead of prefrontal's route. Each command AFT starts gets a one-time ticket in its environment, and the daemon uses it to find the session that started the command; a session id typed on the command line is ignored. Only an agent's own session can post as its bot, so a background worker's bot write is refused. A retried write reuses its request id, so it is never posted twice, and a write whose outcome is unknown is reported as such rather than resent. `gh issue comment` still prints the comment URL.

## Fixes

- The AFT status bar reaches agents again. It had been dropped on both transports: it was sent as a separate field that the plugins discard, and it was hidden whenever a route to the fleet status holder existed, even when nothing displayed it. It is now the last line of the tool result when a count changes. It is hidden only for an OpenCode session whose status the fleet holder has recently reported as displayed, and a category with no value yet shows `?` instead of hiding the whole bar. (#331, reported by @iceteaSA)
- Pi: a headless `pi -p` run exits once it has answered. It used to stay alive for about 60 s because of a startup timer that was never cleared, and never exited with pi-magic-context loaded, because late startup work or a reconfigure brought back a bridge that nothing would stop. `SIGTERM` and `SIGINT` now always end the host after at most 5 s of cleanup, in both plugins; Pi's own handler and AFT's used to wait for each other. The last lines of the plugin log are no longer lost at exit. pi-magic-context's child processes skip AFT's eager startup work (warmup, ONNX Runtime preparation, LSP auto-install) and pay it on their first AFT call instead. (#336, reported by @johnpwilkinson)
- Linked worktrees with `worktree.ram_overlay` see changes that existed before AFT started. The borrowed search index applied only edits made after startup, so branch commits, uncommitted edits and untracked files were missing while search reported ready. It is now compared with the disk before it reports ready, and a watcher rescan no longer throws away the session's edits. (#337, #338, reported by @johnpwilkinson)
- Linked worktrees no longer always load the shared search index as partial. `.git/info/exclude` was fingerprinted under different paths in the main checkout and in each worktree, so the rules always looked different. Existing indexes for a repository's top level are not rebuilt by the upgrade. (#339, reported by @johnpwilkinson)
- A session opened in a subfolder gets its own search index. It used to overwrite the repository-wide shared index with just that subfolder, after which linked worktrees found nothing outside it. A subfolder index left behind by an older version is detected and rebuilt rather than reported as ready. (#340, reported by @johnpwilkinson)
- Semantic search works on OpenCode 2. The OpenCode 2 entry point skipped ONNX Runtime setup, so every search failed. Both OpenCode entry points now share one startup path. A system ONNX Runtime that cannot load, such as a Homebrew build linked against a removed library, is now skipped in favour of AFT's own download, and `doctor` reports it as ignored and gives the reason. `doctor` also reads the version of the library file that actually loads. (#341, reported by @jjjermiah)
- `aft_safety` checkpoints no longer fail with `No such file or directory` when several sessions wait for the same project's checkpoint lock. Releasing the lock deleted the directory the other waiters were about to use. (#342, reported by @iceteaSA)
- The repeat breaker no longer counts each `write`, `edit` or `apply_patch` call twice: once for its preview and once for its apply. It fired on the second genuine repeat, with doubled counts. (#347, reported by @iceteaSA)
- Glob patterns without `**` stop walking at the depth the pattern can match, instead of descending the whole tree under the literal prefix. The gh shim's credential check used to walk all of `~/.config` this way. (#349, reported by @iceteaSA)
- Linux: a directory deleted before AFT can watch it no longer stops live change detection for the whole project. A directory moved into the project has its contents watched too. Running out of inotify watches still stops the watcher. (#352, reported by @iceteaSA)
- Windows: the file watcher could abort the whole AFT process. When its background thread stopped on its own, it closed the handle the watcher still posted its shutdown signal to; Windows could reuse that handle for the async runtime, which then read the signal as a corrupt event. The handle now stays open until the watcher is done with it.
- The file watcher now gives its exclusion slots to the directories that actually overflowed it, including ignored subdirectories of a directory that is itself tracked. Before, ecosystem directories such as extra `node_modules` copies always ranked first, so a busy ignored directory could never be excluded.
- A tsconfig that `extends` a package (for example `@tsconfig/bun/tsconfig.json`) is resolved through `node_modules`, including a package.json `tsconfig` field. These configs used to be rejected, which turned off tsconfig include/exclude filtering, so diagnostics from excluded files leaked into `aft_inspect` and status-bar counts. (#353, reported by @iceteaSA)
- Bash task retention no longer skips most of its runs. Its lock retry gave up after about 22 µs no matter what its budget said; it now waits up to 10 ms, measured by elapsed time. (#354, reported by @iceteaSA)
- Old background task records with 8-character ids, whose processes are gone, are removed on load instead of logging a warning every time. A record whose process is still running is kept. (#355, reported by @iceteaSA)
- Incremental callgraph refreshes load only the files they need instead of the whole graph on every edit. On a 6,761-file repository, a comment-only save went from 1.4 s to 0.36 s, and the refresh's peak heap went from 62 MiB to 14 MiB. This addresses the largest of the four findings in #214. (reported by @iceteaSA)
- Incremental callgraph refreshes now produce the same graph as a cold build. Before, calls in unchanged files could keep stale targets when a method moved, a same-named method was added or removed, a barrel's re-exports changed, or a file one of their imports pointed at was created. Cold builds no longer resolve calls to test globals and other unresolvable packages (`describe`, `it`, `expect` from `bun:test`) to an unrelated source file. Rust `pub use` of a declared module now resolves to the right file.
- The `aft` process no longer crashes with `SIGSEGV` at exit when a semantic build is still running. Exit now waits briefly for ONNX Runtime work to finish, and if it does not finish in time, skips native teardown.
- The callgraph store no longer mistakes two spellings of the same project folder (on Windows `C:\...` and `\\?\C:\...`, on macOS `/var/...` and `/private/var/...`) for two separate clones. It used to rebuild the whole graph and then refuse the next build for a cooldown, so `aft_inspect` could report dead code as failed on Windows.

## Security and logging

- Undo backups are written owner-only (files `0600`, directories `0700`) instead of `0644`/`0755`, so a backup of a private file is no longer readable by other users. Durable checkpoints and log files get the same modes. Existing backup and checkpoint stores are tightened in small, resumable passes during maintenance, and existing log files are tightened too. (#346, reported by @iceteaSA)
- Durable log lines are scrubbed of credentials before they are written: GitHub tokens, `sk-` keys, JWTs, AWS access key IDs, `Authorization` header values, passwords in URLs and credential query parameters. The sanitiser `doctor --issue` uses for bug reports masks the same patterns, and now also catches `ghu_`/`ghr_` tokens and tokens inside URL query strings. A request line that fails to parse is logged by length and hash instead of in full, because it can contain command text or file contents.

## Other changes

- In a subagent session, `bash_watch` without a timeout now waits up to `bash.watch_sync_max_ms` instead of 30 s, so subagents no longer poll in 30-second steps. Primary sessions keep 30 s. On Pi, headless child processes count as subagents.
- The `aft_delete` description now says that deleted contents stay in the undo store.
- The tool list AFT advertises to subconscious clients no longer includes three fields only its own plugins set (`shell`, `foreground_orchestrate`, `block_to_completion`), and lists the `powershell` tool only when `pwsh` is installed. A model given the full list used to fill in `shell: "powershell"` on hosts without PowerShell, and every bash call failed. A PowerShell request on such a host is still refused, and the message now names both fixes.
- AFT's subconscious manifest declares the services it connects to (fleet status, and the embedding service when that is the configured backend). The daemon does not act on this declaration. (#345, reported by @iceteaSA)

## Diagnostics

- Linux memory-relief reports show both what the allocator reports freeing and the drop in resident memory, because `malloc_trim` returns memory in a way the old figure never counted. "Slack" is now labelled as address space, not resident memory. (#344, reported by @iceteaSA)
- The disk-write report attributes callgraph cold-build staging writes to their own category, measured while the build runs, instead of leaving them unexplained.

## For contributors

- Test runs write `aft-plugin-test.log` under the system temp directory instead of the live AFT log directory. (#348, reported by @iceteaSA)
- `scripts/rust-test-gate.sh` gives each run its own XDG config, state, cache and data homes under `target/aft-gate-home` (override with `AFT_GATE_HOME_ROOT`, which replaces `AFT_GATE_XDG_DATA_HOME`). It also clears the git-config and co-author variables an AFT agent shell injects, so gate runs no longer read your user config or rewrite live gh shim state. (#350, reported by @iceteaSA)
- A full Rust test run leaves 13 entries in `TMPDIR` instead of about 60, and none of the remaining ones come from the sources the issue listed. (#351, reported by @iceteaSA)
- The integration harness keeps semantic indexing off unless a test asks for it, so tests do not load ONNX Runtime or download the model.
- `ARCHITECTURE.md` and `STRUCTURE.md` have been rewritten as short maps of the current code. The pull request template now asks for `Approved issue: #N`, and `CONTRIBUTING.md` no longer asks for a closing keyword, which would close the issue at merge, before the release that ships the fix.

## Upgrading

- **Retired keys.** `tool_surface`, `hoist_builtin_tools`, top-level `enabled`, `search_index`, `experimental_search_index`, `semantic_search`, `experimental_semantic_search`, `callgraph_store`, `github.enabled` and the `aft_*` host tool names in `disabled_tools` still work in 0.58, with a migration notice, and are rejected from 0.59. Run `npx @cortexkit/aft doctor --fix` to rewrite them.
- **Rejected now.** `gh_read` and `gh_shim.enabled`, deprecated since 0.56 and still accepted with a warning in 0.57, are now rejected (`removed_config_key:gh_read:use:github.read`, `removed_config_key:gh_shim:use:github.shim`). A config that contains either is not used at all: AFT registers no tools and starts no indexing until `doctor --fix` rewrites it. `aft setup` and `doctor --reconfigure` refuse until then. A `gh_shim` block with only `binary_path` still loads.
- **New defaults.** All three indexes are on, including semantic. `aft_callgraph`, `aft_search`, `grep` and `glob` are registered unless disabled. `aft_move` and `aft_delete` are off until you remove them from `disabled_tools` (or tick them in `aft setup`). Values you set explicitly, including old keys such as `search_index: false`, are still honoured.
- **Semantic model download.** With the local backend, the first semantic build may download an ONNX Runtime and the embedding model and will use CPU while it embeds the repository. Set `indexes.semantic: false`, or untick it in `aft setup`, if you do not want that.
- **`enabled: false`** no longer keeps AFT from indexing a repository. Set `indexes.trigram`, `indexes.semantic` and `indexes.callgraph` to `false` as well.
- **Project configs** can only turn tools and indexes off, not on. A repository that used to enable `aft_callgraph` or an index for itself now needs the user config to allow it.
- **Embedding model cache.** When `FASTEMBED_CACHE_DIR` is not set, the model cache now honours an absolute `XDG_CACHE_HOME` (`$XDG_CACHE_HOME/fastembed`) instead of always using `~/.cache/fastembed`. The plugins set `FASTEMBED_CACHE_DIR` themselves when they start AFT directly, so this mostly affects the daemon and the CLI. If your `XDG_CACHE_HOME` points somewhere else, the model is downloaded once more there.
- **`aft_search` with no ready index** now returns `search_lanes_unavailable` or `no_search_lanes_enabled` instead of a filesystem grep. Use `grep` for text search until an index is ready.
