# v0.65.0

AFT 0.65 brings AFT's read-only tools into OpenCode 2's Code Mode, adds running shells and an AFT status command to the CortexKit apps, and fixes the problems reported after 0.64. Search and grep no longer spike memory on large growing files, TypeScript monorepos start far fewer language servers, and shell waits survive the computer going to sleep.

## Upgrading

- `views.enabled`, `views.callgraph_copies` and `worktree.ram_overlay` are now refused in user config, as 0.64 announced; `npx @cortexkit/aft doctor --fix` removes them.
- New setting `lsp.max_servers` (default 8) caps how many language servers AFT runs at once; a project config can only lower it ([docs](https://github.com/cortexkit/aft/blob/main/docs/config.md)).

## New

- OpenCode 2: AFT's seven read-only tools also work inside Code Mode as `tools.aft.code.*`, with the same permissions (#1004, thanks @iceteaSA).
- The CortexKit apps can list running agent and worker shells, stream their output, and show an "AFT status" command.
- Pull-request reads show review-thread IDs and whether each thread is open or resolved.
- Release downloads include Linux debug symbols and Windows PDBs, so crash reports can be symbolized.

## Changed

- TypeScript packages in one repository share a language server per TypeScript version instead of starting one each (#1434, thanks @iceteaSA).
- On Linux, agent shell commands are killed before AFT or your desktop when memory runs out (#750, thanks @iceteaSA).
- Plugin tool guidance is shorter, and the toolkit is now named Agent Foundational Toolkit.
- `aft_search` right after a project opens waits up to 8 seconds for its first index instead of asking you to retry.
- Build-server reports list at most 20 files that weren't copied back, plus a folder summary.
- AFT uses far less idle CPU when many finished shell commands are saved.
- An unconfirmed shell outcome now names the task, any build-server job and its output, and how to check before retrying.

## Fixed

- Search and grep read files over 4 MiB in small steps, so large growing logs no longer cause multi-gigabyte memory spikes or slow status replies (#1432, thanks @tobwen).
- Shell waits and request deadlines count time the computer was asleep, and a started command is never reported as unknown after sleep (#1439, thanks @null-axiom).
- Rust diagnostics no longer stay "provisional" when a macro includes files through a computed path (#1425, thanks @elmagow).
- Shared temporary folders such as `/tmp` are never watched or indexed as projects, and unreadable folders are reported as index gaps (#1428, thanks @iceteaSA).
- grep in a folder of repositories searches a repository whose index is still loading, instead of answering "Found 0 matches" (#1423, thanks @iceteaSA).
- Temporary-folder refusals name the file and the rule that blocked it (#1421, thanks @iceteaSA).
- On Windows, the grep hint no longer misreads backslash paths outside the project (#1436, thanks @aurele-l).
- OpenCode 2 no longer opens AFT routes in unrelated folders for another location's sessions (#1442, thanks @iceteaSA).
- macOS CPU profiling no longer hangs while symbolicating.
- TypeScript 7's native language server shuts down cleanly.
- `gh --jq` failures that print nothing now say how jq ended.
- `runon` file returns work from a side worktree and allow up to the runner's 128 MiB.
- A build-server job killed for memory says whether to rerun with more memory.
- Killing a queued build-server command cancels it on the server and says so only when confirmed.
- AFT answers immediately after a restart even with a long shell history.
- A config edit made while AFT was still starting is picked up instead of missed.
- Status dialogs show unknown checkpoint counts as `—` instead of 0.

## Security

- If the GitHub shim can't verify itself, agent shells refuse `gh` instead of falling back to your personal GitHub login.
- Shell command logs and issue reports mask inline passwords and redact project folders, home folders and user names.
- `{{ck-secret:<label>}}` placeholders use the live CortexKit vault, checking every request's real host and path before inserting a key.
