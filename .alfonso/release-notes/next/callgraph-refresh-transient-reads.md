- The first call-graph refresh after AFT loads or publishes a checkout's call graph no longer keeps a decoded copy of every file it only checks. That covers a new worktree's first edit, the first edit after a restart, and the first edit after each publication. That refresh used to hold every stored parse, plus the resolutions of every file that reads the edited one, until it finished. On AFT's own repository, one edit to the crate root held about 1.5 GB, and three new worktrees refreshing at once took the process to about 6 GB. The same edit now holds about 360 MB, three worktrees at once peak at about 2 GB, and a refresh takes about as long as before. It returns the same answers as before.
