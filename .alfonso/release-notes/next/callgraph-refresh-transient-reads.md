- The first call-graph refresh after AFT loads or publishes a checkout's call graph no longer keeps a decoded copy of every file it only checks. This covers a new worktree's first edit, the first edit after a restart, and the first edit after each publication. That refresh used to hold every stored parse, plus the resolutions of every file that reads the edited one, until it finished. On AFT's own repository, one edit to the crate root held about 1.2–1.6 GB. Three new worktrees refreshing at once took the process to about 5–6 GB. The same edit now adds about 300 MB, three worktrees at once peak at about 1.8 GB, and the refresh takes no longer than before. It returns the same answers as before.
