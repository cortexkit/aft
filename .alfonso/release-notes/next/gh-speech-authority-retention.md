- AFT now deletes GitHub bot-write authorities from `aft.db` once they have been revoked for 24 hours. Every shell launch in a bot-enabled session stores one row of about 84 KB in `gh_speech_authorities`, and nothing deleted revoked rows, so on a busy machine the table reached 7 GB and grew by about 600 MB a day. The once-a-minute retention worker now deletes at most 64 such rows per transaction, for at most 100 ms per minute, and logs `speech authority retention: examined=… deleted=… batches=… exhausted=… stopped=… vacuum_pages=… elapsed_us=…` (INFO when it deleted something, DEBUG otherwise). On a synthetic table of 100,000 revoked 84 KB rows it deleted about 2,300 rows a minute, 5 ms per transaction, with the data still in the operating system's file cache. Active and candidate authorities are never deleted. The revocation records stay, so a deleted authority's ticket is still refused, now as `ticket_unknown` instead of as revoked. Authorities that a write queued by an older AFT build still refers to are kept.
- Revoking an authority now also drops its copy of the signed routing manifest, which was most of the row. A revoked row takes about 1 KB until it is deleted. The manifest itself stays in `aft.db`'s policy ledger.
- Deleting rows leaves free pages inside `aft.db`. The file does not shrink by itself; SQLite reuses the free pages for later writes, so the file stops growing. AFT databases use SQLite's default `auto_vacuum=NONE`. A database converted to `auto_vacuum=INCREMENTAL` returns up to 4,096 free pages (16 MiB) to the file system each minute.
