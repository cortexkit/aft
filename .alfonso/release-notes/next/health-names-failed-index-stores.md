- When roots' index stores fail to build or refresh, the daemon's health report now names them instead of giving only a count. `metrics.data_store_failed` lists up to five roots in path order, each with its reason code (for example `bind_failed` or `build_failed`), and `metrics.data_store_failed_omitted` counts the rest. The `detail` sentence names the same roots, for example `1 root(s) could not build or refresh their index store: /Users/me/Documents (bind_failed); see roots[].data_store`. The names add at most 1 KiB to the detail, and the metrics stay within their 12 KiB budget.
