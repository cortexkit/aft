# v0.64.0 (a.k.a AFT goes brrrr....)

AFT 0.64 rebuilds the engine under every tool. One index store, shared by every checkout of a repository, replaces the separate text-search, call-graph and meaning-search indexes. What we measured:

| On AFT's own repository (about 7,300 files), on a dedicated 8-core Linux server | 0.63 | 0.64 | |
|---|---|---|---|
| Call graph built from scratch | 1,030 s | 40 s | **26x faster** |
| An ordinary edit reaches the call graph | 7.9-13.2 s | 0.8-2.0 s | **about 9x faster** |
| Call graph matches a fresh rebuild after each of 19 commits | 10 of 19 | 19 of 19 | **always right** |
| Index disk for the repository | 1.9 GB | 0.5 GB | **4x smaller** |
| Dead-code check, first run | 89 s | 23 s | **4x faster** |
| Dead-code check after an edit | 33 s | 12 s | **3x faster** |
| Adding a new Rust module reaches the call graph | 5.1 s | 4.7 s | about the same |
| TODO count after a restart | 5.5 s | 1.7 s | **3x faster** |
| Peak memory during these steps | 4.7-7.5 GB | 1.5-2.4 GB | **3x less** |

Each repository rebuilds its indexes once after upgrading.

## Upgrading

- Each repository builds its new indexes once, on first use: text search in about a second, the call graph in under a minute for large projects. Worktrees of one repository share them.
- Meaning search reuses the previous index's vectors for unchanged files embedded with the same model; other files are embedded once per repository, not once per worktree.
- Old index folders stay on disk. `npx @cortexkit/aft cache prune-legacy` lists them with their sizes; add `--yes` to delete them ([docs](https://github.com/cortexkit/aft/blob/main/docs/cli.md)).
- `views.enabled`, `views.callgraph_copies` and `worktree.ram_overlay` no longer do anything and show a notice; 0.65 will refuse them. `npx @cortexkit/aft doctor --fix` removes them.
- `views.idle_checkout_hours` is now `idle.checkout_hours`; AFT rewrites your user config automatically ([docs](https://github.com/cortexkit/aft/blob/main/docs/config.md)).
- `inspect.tier2_idle_minutes` no longer does anything and shows a notice, since whole-repository analyses now run only on `aft_inspect`.
- Config names retired in 0.62 or earlier, such as `tool_surface`, `search_index` and `sandbox.enabled`, are refused in user config with `removed_config_key`; project configs still load with a notice. `npx @cortexkit/aft doctor --fix` rewrites them.

## New

- `trace_to` follows callers to the real roots and labels each one: main, test, attribute, public API, or no caller found. `impact` uses the same labels.
- `call_tree` and `trace_to_symbol` follow calls written inside Rust macro templates, marked approximate.
- `gh --status` shows the 10 newest operator-bypass entries; `gh --status --audit` prints the full list.
- The CortexKit apps list the folder access you saved for agents and workers, and you can revoke it there. A revoke takes effect at once: running commands that use that folder are stopped and show `killed (folder access revoked)`. Each grant says who gave it (you, or an agent passing on access), and grants left behind by finished workers are removed automatically. Grants saved before this version show "granted before" the upgrade time, since their exact time wasn't recorded.

## Changed

- An edit now re-resolves only the files that read what it changed. Adding a function to a file that many others use used to re-resolve about 1,500 files on AFT's repository; it now re-resolves 1. Ordinary edits like it reach the call graph in 1-3 seconds instead of 7-13. Adding a new Rust module checks only the files that look that module up, so it takes about 4.7 seconds. An edit that really does change something hundreds of files read takes up to 13% longer than before.
- Dead-code and unused-export checks use a fraction of the memory they did.
- Dead code, unused exports, duplicates, cycles and complexity are computed only when `aft_inspect` is called, never in the background. The status bar shows errors, warnings and TODOs (`[AFT E1 W3 | T5]`), and the OpenCode sidebar no longer has Dead Code, Unused Exports and Duplicates sections.
- TODO counts come from the index store, which records each file's TODO markers when it indexes the file, so counting them no longer parses any file.
- A new worktree starts from a sibling checkout's indexes and processes only the files that differ: on a 7,300-file repository, under a second instead of about 40 seconds on every core.
- A repository's index store keeps a bounded number of segment files however many worktrees edit it, and AFT keeps at most 1,024 of them open at once. Tidying a busy worktree's segments copies the stored data instead of rebuilding from source: under a second and a few tens of MB on a 7,000-file repository, instead of about 12 seconds, 40 seconds of CPU and over 1 GB.
- A busy worktree's call graph holds about a tenth of the memory it did (on AFT's own repository, about 120 MB instead of 1 GB), and all worktrees share one set of resolver threads.
- Several worktrees updating their call graphs at once no longer briefly take several GB: three on AFT's own repository peak at 2.0 GB instead of 5.9 GB.
- `aft_search` is faster under load: each search reads a candidate file once instead of up to eight times, and searches no longer wait on each other's embedding calls. With eight at once, the median search takes 84 ms instead of 144 ms, with about a third less CPU and half the disk reads. Choosing the line to show for each result also no longer builds two strings per line of every candidate file, which makes busy concurrent searches a further 25% faster.
- Edits wait less on their undo snapshot: one fewer full disk flush on macOS, and a busy undo index never holds an edit for more than 50 ms.
- Opening a worktree whose files match a sibling's no longer decodes every file's symbols: about 0.2 s instead of 1.1 s, and 16 MB instead of about 1 GB of short-lived memory.
- Background TODO counts and the configure warning pass take their file list from the index store instead of walking the whole project.
- `aft_outline` on Rust files with traits is several times faster, reading a tagged file no longer hashes it, and meaning search checks for new vectors without rereading its index.
- AFT's log names the operation behind any very large memory use, to help with reports.
- The index store stays small over time: meaning-search updates are merged instead of piling up, and a worktree that has gone quiet is compacted by the others instead of keeping every old copy. On AFT's own repository with ten worktrees, the store went from 5.2 GB to 1.9 GB.
- AFT's database no longer grows by about 600 MB a day on machines that use the GitHub bot: finished commands' bot-write records are deleted after 24 hours and are 1 KB instead of 84 KB.
- `write`, `edit` and `apply_patch` no longer parse the edited file before returning; search sees the edit at once and the call graph parses it on its next refresh.
- Text search is ready about a second after a repository opens, before the call graph finishes; `grep` and `glob` walk the folder until then.
- The call graph and meaning search skip minified bundles (`*.min.js` and single-line JavaScript or CSS); text search still covers them.
- `aft_search`'s "N of M candidate files" now counts the files it actually examined.
- When free disk falls below AFT's reserve, index storage pauses and status says so, instead of tools failing.
- An index store written by a newer AFT is refused by name and left untouched, so going back a version never deletes it.
- Tool replies are capped at 50 KB; a cut reply ends with the path of a file holding the full result.
- Sessions hosted by CortexKit's session runners get the same tools, tool names and trust as OpenCode on the same model, including Claude Code and Pi sessions; a finished background command can start their next turn.
- `bash` with `background: true` from a runner-hosted head answers at once with the task id.
- In a runner-hosted session, sending a message while `bash` or `bash_watch` waits on a long command hands the call back within a few seconds; the command keeps running and its result arrives as a notice.
- The `bash` and `bash_watch` descriptions tell agents to start independent work before waiting on a long command.
- Background tasks started from a code-mode program keep running after it ends and notify the agent it ran for; their notices and controls follow the caller that launched them. A delegated worker can watch the tasks its own code-mode program starts.
- On macOS, a folder search that meets folders macOS protects skips them and names them in the reply, instead of failing and asking you to grant access to each one. AFT withdraws the access requests earlier versions filed this way.
- Code-mode programs can ask for permission and get the tool result after you answer.
- After a restart, background commands without secrets, including shells using an SSH agent, keep their output previews.
- A `bash` call cut by a restart names its task, so you can watch or stop it.
- Long tool calls that are still making progress (shell commands, watches, inspections) are no longer cut by a runner's 90-second silence rule.
- Reconnecting, settling tool calls, saving shell output and cleaning up old command records use far less CPU and disk on machines with long histories.

## Fixed

- Call graphs find many more real callers and fewer wrong ones in Go, Python, TypeScript and Rust, including Python callers across files and through `import pkg.mod` (#1126).
- Call-graph queries no longer wait up to 30 seconds for a refresh when the machine is busy.
- One case is slower than in 0.63: if AFT stops within seconds of an edit, before it saves that edit, the first call-graph query after the restart takes about 5 seconds instead of about 1.
- The call graph no longer reports itself current while edits made during an index build are still unresolved.
- `.h` headers written in C++ or Objective-C get outlines, symbols and call graphs; plain C headers are unchanged (#1199).
- `grep` and `aft_search` find files in a folder moved into a project on macOS or Windows.
- Concurrent edits of one file from two sessions no longer lose an edit; the second write is refused (#1223, thanks @iceteaSA).
- `aft_inspect` no longer reports old diagnostics or a false clean result right after a change, or misses Rust compiler errors (#829).
- `aft_inspect` on several files outside the project no longer fails after the first approval (#1258, thanks @iceteaSA).
- `aft_inspect` returns partial results before the client's deadline, and its dead-code checks skip generated files and files over 4 MiB (#1337).
- Meaning search keeps going when an embedding provider refuses some chunks, and no longer sends image data URIs that vision-enabled providers reject (#817, #819, thanks @citizenadam).
- AFT starts inside Linux sandboxes that allow its storage folder but deny reading `/` (#1245).
- A session with no project folder gets a clear refusal for file tools instead of treating the filesystem root as the project.
- On Windows, an edit no longer makes the file briefly disappear, and downloaded files keep their downloaded-from-the-internet marker.
- Folder approvals that arrive after a call stops waiting cover later reads; `cd $DIR` no longer makes approvals name the home folder.
- Config reload notices edits to symlinked config files; `doctor` keeps newer OpenCode plugin versions and finds OpenCode 2 installs.
- On macOS, privacy prompts for commands AFT runs name AFT's daemon at its installed path, so allowing it once is remembered.
- Recursive `aft_delete` of a large folder is about four times faster on macOS and stops before deleting anything when it runs out of time.
- A shell command the host refuses now says so, instead of reporting an unfinished permission loop.
- Shell commands no longer leave a GitHub start-view file behind each time (some machines had tens of thousands, several GB), and starting a shell no longer scans them; old ones are cleaned up automatically.
- In Pi with hashline edits on, the edit row shows the edited files and their diff instead of an empty row (#1410).
- In OpenCode 2, file tools follow a session moved to another repository, instead of reading relative paths in the old one (#1413).
- Projects whose `typescript` package is a TypeScript 6 shim get diagnostics again: AFT finds the real TypeScript the shim depends on. A TypeScript server binary set in `lsp.servers` now manages its own TypeScript install (#1416).
- The health report names the repositories whose indexes can't be built, and why (for example, a folder macOS doesn't let AFT read).
- A background command that finished while AFT was restarting, or while a session was reconnecting, now reaches the agent when the session reconnects, instead of being lost.
- The GitHub guard refuses an operator command run from a shell that holds bot credentials, instead of sending it with the bot's login under an operator entry in the audit log.
