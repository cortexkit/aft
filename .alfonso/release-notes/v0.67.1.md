# v0.67.1

AFT 0.67 makes call graphs more precise for C#, Java and TypeScript and cuts the memory that large call-graph builds and refreshes need. It also keeps status and version answering while an index builds, fixes an ONNX Runtime download that broke new installs, and fixes the problems reported since 0.66.

## Upgrading

- This version reindexes: each project's call graph is rebuilt once, automatically, the first time it is used after the upgrade. Text and meaning search indexes are kept.
- AFT updates your user config to current setting names the first time it reads it, and keeps the old text in its data folder. The changes: `bash: true` or `false` becomes a `bash` object, `lsp.idle_minutes: "never"` becomes `lsp.idle_shutdown: false`, `storage.cache_dir` becomes one setting with three named choices, and language-server `initialization_options` are stored as JSON text. AFT never rewrites a project config: one with an old spelling keeps working with the current equivalent, and a notice suggests running `npx @cortexkit/aft doctor --fix` in that project ([docs](https://github.com/cortexkit/aft/blob/main/docs/config.md)).
- On Windows, the user config moves from `%USERPROFILE%\.config\cortexkit\aft.jsonc` to `%APPDATA%\cortexkit\aft.jsonc`, the same folder the CortexKit daemon uses. AFT moves it on first start and keeps a copy of the old file in its data folder.
- `callgraph_chunk_size` is removed (it never had an effect). A user config that still sets it is refused until you run `npx @cortexkit/aft doctor --fix`; a project config's value is ignored with a notice.
- Storage from before 0.27 is no longer migrated: upgrade through 0.66 first. `aft clean-old-caches` is now `aft cache clean-old`.
- Building from source: AFT's lowest layers are now their own crates (`aft-base`, `aft-db`, `aft-parse`), published to crates.io beside `agent-file-tools`.

## New

- OpenCode 2: `/aft-tasks` lists and stops the session's background commands (#1471, #1475, thanks @KomeijiReimu).
- A `memory` setting in the user config: `lean` uses a smaller cache, four call-graph threads on Linux and macOS, and returns freed memory at once on Linux; `balanced` keeps today's limits. Computers with less than 8 GiB of memory pick `lean` automatically.
- `aft --help` prints usage and exits without starting the server; unknown commands exit with a usage error (#1466, thanks @iceteaSA).
- grep names the folders that ignore rules kept out of a search (#1289, thanks @jjjermiah).
- Reading a missing path outside the project that matches exactly one file inside it answers with a "did you mean" suggestion.

## Changed

- Call graphs: calls on a type name, such as `Tuple.Create(...)` in C#, `Foo.bar()` in Java or a class method in TypeScript, resolve to that type's method instead of every method with the same name. In our tests, name-only links dropped by up to 17% (Spring), unused-code reports stayed the same, and peak memory stayed within 5% (#1441, thanks @OlegAndreych).
- Patch and edit diff previews are capped at 128 KiB per response, with a note when a preview is cut (#1291, thanks @jjjermiah).
- In a session opened on a folder that holds several repositories, `aft_search` with only a pattern searches every repository, and pattern plus query keeps the pattern (#1480, thanks @iceteaSA).
- ONNX Runtime for local meaning search now downloads from Microsoft's NuGet package, with the same hash checks.
- The direct `undici` dependency is removed (#1431, thanks @trim21).
- The npm macOS binary is signed with hardened runtime.

## Fixed

- Large call-graph builds and refreshes use much less memory. In our Linux tests: the Linux kernel's first build went from 3,977 MiB to 1,712 MiB, .NET's from 3,242 MiB to 2,119 MiB, and the .NET unused-code report from 866 s and 18.7 GB to 129 s and 2.9 GB. A refresh that would outgrow a full rebuild now stops and rebuilds instead: on VS Code, a refresh after editing 10% of files peaked at 2.3 GiB instead of 14.8 GiB (#1441, thanks @OlegAndreych).
- New installs could not download ONNX Runtime, because its GitHub repository was removed; downloads now come from Microsoft's NuGet package.
- AFT starts on Linux kernels before 5.8, such as RHEL 8 (#1468, thanks @henry-hsieh).
- `status`, `version` and `ping` answer within milliseconds while meaning search builds its index, instead of waiting up to a minute, and the plugin's hang watchdog no longer restarts a busy AFT as hung (#1482, #1483, thanks @tobwen).
- A plugin tool call that times out or races a plugin reload now says whether its change may still have happened and whether it is safe to retry (#1292, #1295, thanks @jjjermiah).
- An edit whose text matches many times on a very long line no longer uses gigabytes of memory, and a loose-match edit no longer deletes a trailing blank line.
- An edit could be lost when a stale file-watch event arrived after it; a search could answer empty while an index was being replaced; a search index shared by worktrees of one repository could lose vectors another worktree still used.
- Output watches no longer match half-written lines, a restarted AFT checks whether a terminal session is still running before reporting it killed, and a kill after restart confirms the process ID still belongs to the task.
- Shell results and display records no longer read a command's whole output into memory.

## CortexKit

- An agent on a paired computer can use this computer's AFT on a registered folder, after a person approves on this computer. Remote shells run only on Linux computers for now.
- On Linux, background commands keep running when AFT restarts under the daemon: each runs in its own systemd user scope when a user manager is available, with a 24-hour default ceiling (`bash.linux_scope_max_runtime_secs`) (#1109, #1219, thanks @iceteaSA).
- Remote runs are one user switch, `remote_exec.enabled`; `bash.runon_enabled` is retired and migrated automatically.
- AFT reads its settings through Subconscious when the daemon offers it, ready for the desktop settings pages.
- The apps: bash rows are one line with a red icon on failure, finished commands show their last output lines, and background-command notices get their own cards.
- Program calls work right after an AFT restart; background commands a program starts notify the agent; head agents read their own repository's linked worktrees without an approval card.
- Read-only folder approvals cover the holding repository, approval cards nobody returns to are withdrawn after 30 minutes, and agents can read and edit the CortexKit settings folder while data folders stay blocked.
- The secret proxy passes compressed and large header-authenticated uploads through, keeps a held connection alive after a long approval, and names the reason in every refusal.
- AFT shares one search-reranking connection per agent harness instead of one per project, fixing a connection leak that blocked build-server jobs.
- Scope ends come from the daemon's watch instead of polling, and only a confirmed end stops a session's processes.

## Security

- A patch that moves a file onto or from a symbolic link can no longer read or write outside the project folder.
- CortexKit: revoking a folder approval stops the commands that approval started, also after the folder has moved.
- CortexKit on Linux: shell commands can no longer change the installed AFT binary or its metadata; the daemon's AFT runs from a private copy in protected storage (#1422, #1424, thanks @iceteaSA).
