AFT 0.57.0 fixes two daemon-wide stalls that made every tool time out for every session on a machine — a temp-directory scan that pinned the executor, and a scheduler that stopped refreshing one project while serving all the others — and closes a crash in the integration suite that had been aborting CI for a week. It also stops three classes of runaway background work (a build tool rewriting one `.gitignore` byte no longer rebuilds the corpus), adds per-period disk-write attribution so the next write storm names its source, and moves the contributor gate to a fleet-shared workflow.

## Highlights

- **Route binds no longer stall behind a temp-directory scan.** The transient search-cache sweep listed the entire shared `$TMPDIR` before applying its own 200-entry cap; with 290,000 entries from other tools' test scratch, one listing took ~870 s, six of eight executor workers sat inside it, and every new session on the machine was refused with "did not answer route.bind within 12s" while established sessions kept working. AFT's scratch now lives in its own subdirectory so the sweep is proportional to AFT's own files, the cap and deadline apply at the iterator, and the log reports what was examined, not only what was removed.
- **A project the scheduler forgot.** Tier-2 refreshes (dead code, complexity, duplicates) stopped dispatching for the most-used project on a machine while every other project refreshed normally; the health report kept publishing a deadline nothing honoured. The scheduler's only tick ran inside the watcher drain, the drain ran only when there was watcher work, and the tick recorded changes before checking its own quiet window — so the quiet window it waited for was exactly the window with no tick in it. A quiet project is now pumped by the maintenance tick, a limiter refusal backs off instead of retrying four times a second, and the daemon logs once, at info, when a published deadline passes without dispatch and why.
- **An ignore-file rewrite is no longer a corpus rebuild.** Build tools rewrite nested `.gitignore` files continuously (`worker-build` writes a one-byte `*` into `build/.gitignore` on every run); each rewrite was read as a rule change and rebuilt the search index — 28 builds in fourteen minutes, 27 GiB/h of disk writes. An ignore file that is itself ignored is not a rule change; byte-identical rewrites trigger nothing; a change that only adds exclusions retires the newly-excluded paths instead of re-walking; a rebuild that is still needed is scoped to the changed file's subtree.
- **Disk-write attribution.** `aft profile --writes --since 2h` (and `--live 60`) shows physical bytes written per subsystem and project over any window, with SQLite checkpoint backfill credited and an explicit unattributed remainder; the health report names the top three writers of the last ten minutes, and the sentinel alerts on the rate. This is the instrument that found the ignore-rewrite loop above.
- **The integration suite no longer crashes on CI.** Three different storm tests aborted with SIGBUS on both Unix runners: callgraph cold-build publication renamed the database to its generation path but left its `-wal`/`-shm` at the stable staging name whenever a second connection kept SQLite in WAL mode, and the next build at that name adopted the stale WAL-index and truncated it under a live mapping. The sidecars are removed with the rename, a detector reports two live connections on different files at one path, and the suite captures a symbolized backtrace and core on any future fatal signal.

## Fixes

- `edit` tells the model what is missing. The advertised schema is flat (hosts refuse root-level unions), so `{path, symbol}` passed validation and was rejected at runtime with a bare message; kimi-class models retried it nine times in a row. The tool text now states that `symbol` and `content` are only meaningful together, and the rejection names the missing or null property and both complete shapes. (#323)
- Hashline `PUT 2: INLINE` reports the body-row rule instead of "registers must begin with @". Trailing same-line text after a body-bearing address was parsed as a register reference. (#324)
- Remote embedding backends that are slow are no longer classified as dead and re-collected from scratch. One 25 s deadline covered a whole 64-chunk batch and was retried three times unchanged, so a backend at 2 s per item could never finish; the deadline now scales with batch size and measured latency, a timeout halves the batch, and recovery re-embeds the failed file set instead of re-walking the corpus. `semantic.query_timeout_ms` accepts up to 30 s. (#310, #320)
- Windows: the ONNX runtime download extracts through `%SystemRoot%\System32\tar.exe` by absolute path (an MSYS2 `tar` on `PATH` read `C:\` as a remote host), and `doctor --fix` downloads before it deletes the existing runtime. (#321)
- PTY bash tasks resolve their shell through the same resolver as pipe tasks. `$SHELL` steered them to the operator's fish or custom shell, so agent commands written for bash failed in ways the agent could not see.
- Background bash completions delivered mid-turn no longer detach a running `wait: true` task and append the older task's footer to the wrong reply; busy deferral is capped at 60 s.
- A background task that completes with a long-running descendant still alive reports it; `bash_kill` on a completed task signals the process group. (#311)
- Concurrent `aft.db` openers no longer wedge on migrations: version steps are planned inside the transaction that runs them, and a database left between V9 and V10 heals itself. Opening a current database takes no write lock. (#312)
- Windows startup no longer downloads the same LSP servers sixteen times: auto-install is coordinated across plugin instances and the archive check uses the same extractor as the install. (#314)
- `aft_conflicts` on a file path returns the file's conflicts instead of ENOTDIR.
- Governed `gh` calls: read-only verbs (`issue view`, `pr checks`, `run download`, `search`, …) delegate to the caller's `gh` instead of refusing as unclassified; author-scoped `issue edit` is classified; a probe that times out after the request was sent reports "outcome unknown" (exit 87) rather than "not run"; the shim's probe budget is 2 s per stage with one retry.
- Embedding-backend outages are reported as `backend_unavailable` with the retry deadline instead of `building`; a project in its refresh quiet window reports `stale` with the next refresh time instead of `building`. Both had been read by the health sentinel as stuck index builds.
- Windows CI: nine test races and path-form assertions fixed; none of them changed product behaviour.

## Changes

- File watcher exclusion slots are seeded by ecosystem (`target/`, `node_modules/`, `build/`, `dist/`, …) including nested copies, and directories that do not exist yet are excluded before they are created, so `bun install` or the first `cargo build` in a fresh worktree no longer overflows the event stream. Overflow log lines name the active exclusions and the path prefixes that produced the events.
- Ignore-rule refreshes coalesce behind a 5 s quiet window; a burst of `.gitignore` writes no longer restarts the index load on every write.
- A same-root `aft_inspect` shares one cold-build slot across its five categories instead of taking five.
- Callgraph refreshes write only the rows that changed; a one-file refresh on a 480 MB store went from ~105 MB of physical writes to ~16 KB.
- The daemon log keeps the newest dead process's log across a supervisor restart (it was the only file large enough to satisfy the directory budget, so it was the one deleted), and reaps relic plugin-log rotations.
- The repeat breaker keys on tool input rather than output, so alternating two calls or appending a timestamp no longer defeats it.
- Contributor pull requests are gated by the fleet's shared design-gate workflow (`cortexkit/subconscious`): a PR without a linked `design-approved` issue is converted to draft on open, and approving the issue marks it ready. The rule and the `trivial` bypass are described in `CONTRIBUTING.md`.

## Configuration

- `semantic.query_timeout_ms` ceiling: 15000 → 30000.
- `bash.linux_scope` (Linux, default off): run background tasks in a transient systemd scope so their descendants are tracked.

## Notes

- Hashline line tags: a report received during this cycle shows the seed-zero digest AFT computes is not xxHash32 for inputs of 16 bytes or more (an xxHash64-style merge was applied after the lane fold). Tags are consistent within AFT, so edits are unaffected; the correction lands in the next release together with independent test vectors, and every tag longer than 15 bytes changes when it does.
- Content-addressed views (`views.enabled`) remain opt-in; this release carries its write-volume and materialization work but no default change.
