# v0.68.0

AFT 0.68 makes background commands safer: a command stops once its output passes 1 GiB, a kill always sends its signal, and Linux memory-cap kills report their cause. Index status now says when indexing is paused for low disk space or waiting for the ONNX Runtime download, and idle file watchers no longer wake constantly.

## Upgrading

- A background command now stops once its output passes 1 GiB, including build-server jobs, so one noisy command can't fill the disk (#1499, thanks @iceteaSA).

## Changed

- A build-server copy waits up to 30 seconds for the same session's running foreground commands in that checkout, and says so if one is still running.
- Moved or copied files reuse their stored index data instead of being parsed again, so large renames refresh faster.
- Meaning search no longer reloads its embedding model when there are no new files to embed.
- Idle file watchers on Linux and macOS no longer wake 20 times a second.

## Fixed

- Linux memory-cap kills now report the cap as the cause instead of an unknown result (#1484, thanks @iceteaSA).
- A kill now always sends its signal, even when AFT can't save the command's state (for example on a full disk), and a command whose Linux scope already ended is reported as stopped (#1499, thanks @iceteaSA).
- When the disk is nearly full, search and status show `paused (low disk space)` with the free space instead of `building` (#1493, thanks @stdweird).
- Search status says when meaning search is waiting for the ONNX Runtime download, and `doctor --fix` replaces a cached ONNX Runtime that doesn't match AFT's pinned build (#1493, thanks @stdweird).
- The status dialog shows the index store's size instead of disk sizes that always read 0 (#1493, thanks @stdweird).
- When `aft_delete` deletes only part of a batch, it names each skipped path and why.

## CortexKit

- AFT declares its settings to the CortexKit daemon, so the desktop app can show them, with setup guidance on first use. Standalone AFT keeps reading its settings files as before.
- Tool catalogs publish tool versions, so a compatible tool update no longer breaks sessions that are already running.
- `write` and `apply_patch` calls get rich rows and pages in the apps; a partly applied patch shows as `Partly applied`.
- Connecting sessions reuse parsed settings instead of reading them again for each connection.
- Notices for a deleted session no longer recreate it.
- AFT's self-check no longer reports a stale health snapshot while it waits for its next refresh.
